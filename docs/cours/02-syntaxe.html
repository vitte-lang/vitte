Le fichier est une suite de déclarations

À la différence d’un script où chaque ligne est nécessairement une instruction immédiate, un fichier Vitte contient surtout des déclarations : module, import, constante, forme, procédure, et ainsi de suite. Une déclaration donne un nom ou une structure que d’autres parties du programme peuvent utiliser.

space tutorials::syntaxe;

const REPONSE: i64 = 42;

proc lire_reponse() -> i64 {
    return REPONSE;
}

proc main() -> i64 {
    return lire_reponse() - REPONSE;
}

Dans cet exemple, le fichier déclare son module, une constante, puis une procédure. L’ordre permet au lecteur de découvrir d’abord le contexte et ensuite le comportement. Le compilateur analyse l’ensemble du fichier pour relier les noms à leurs déclarations.

Exemple vérifié : chemin, constante et procédure

Le fichier complet examples/tutorials/syntaxe.vit appelle la procédure et vérifie que la constante vaut 42.

build/bin/vitte run examples/tutorials/syntaxe.vit --quiet --no-color

Résultat confirmé : code de sortie 0.

La ponctuation a un rôle précis

  • Les parenthèses ( ) encadrent les paramètres d’une procédure ou les arguments d’un appel.
  • Les accolades { } délimitent un bloc, par exemple le corps d’une procédure ou d’une condition.
  • Les deux-points : séparent souvent un nom de son type : REPONSE: i64.
  • La flèche -> introduit le type de retour d’une procédure.
  • Le point-virgule ; termine plusieurs déclarations et instructions.
  • :: sépare des éléments dans un chemin de module ou un nom qualifié.

Un bloc peut contenir plusieurs instructions. L’indentation ne remplace pas les accolades : elle sert aux personnes qui lisent le code. Garde une indentation régulière, car elle rend visibles les blocs imbriqués et les erreurs de fermeture.

Commentaires : écrire pour la prochaine lecture

Un commentaire explique une intention, une règle ou une subtilité qu’on ne peut pas déduire facilement du code. Vitte accepte les commentaires de ligne //, les commentaires de documentation /// et les commentaires de bloc /* ... */. Les commentaires de bloc peuvent être imbriqués dans la grammaire du dépôt.

// La limite est exclusive pour simplifier le parcours.
const LIMITE: i64 = 10;

/// Renvoie le double d'une valeur.
proc doubler(valeur: i64) -> i64 {
    return valeur * 2;
}

Évite de commenter chaque ligne pour la paraphraser. Une bonne explication répond plutôt à « pourquoi cette limite ? », « quelle hypothèse faisons-nous ? » ou « que doit garantir cette procédure ? ».

Noms, majuscules et littéraux

Les identifiants commencent par une lettre ou un souligné, puis peuvent contenir des chiffres et d’autres caractères autorisés. Les noms sont sensibles à la casse : score et Score sont deux noms différents. Le dépôt emploie souvent snake_case pour les procédures et variables, et des majuscules pour les constantes et les types.

Un littéral est une valeur écrite directement dans le code : 42, 3.5, true, 'v', "salut" ou null. Les entiers peuvent également être écrits en binaire (0b1010), en octal (0o12) ou en hexadécimal (0xA). Les caractères spéciaux dans une chaîne se notent avec une barre oblique inversée, par exemple \n pour un saut de ligne.

Lis les signes comme des repères

Quand tu bloques, repère d’abord l’endroit où une déclaration commence, puis le bloc qu’elle ouvre, et enfin les expressions qu’elle contient. Ce parcours de l’extérieur vers l’intérieur réduit beaucoup la confusion.

Un exercice de lecture

Dans le programme de départ, marque la déclaration de module, le nom et le type de retour de main, l’appel à print et le retour. Puis enlève une accolade ou un point-virgule et lance vitte parse. Le diagnostic te montrera quel morceau de ponctuation manquait et à quel endroit le parseur l’a remarqué.

Atelier guidé : annoter et réparer

  1. Prends un fichier court de examples/. Pour chaque ligne, écris en marge « déclaration », « instruction », « expression » ou « commentaire ».
  2. Ajoute un commentaire qui explique une intention, pas le texte déjà visible. Demande-toi si le commentaire restera vrai après une modification du code.
  3. Fais trois erreurs séparées : guillemet non fermé, accolade manquante et point-virgule absent. Utilise lex puis parse pour voir à quelle étape chaque erreur devient visible.
Auto-évaluation

Un lexer identifie les morceaux élémentaires du texte, comme les identifiants et les littéraux. Le parseur vérifie que ces morceaux s’assemblent dans une structure permise. Une erreur sur une chaîne non fermée apparaît donc très tôt ; une accolade oubliée se manifeste au niveau de la structure.
