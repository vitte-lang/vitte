Chemin logique et fichier source

Une déclaration space nomme le module auquel appartient un fichier. Dans le projet d’exemple, les sources se trouvent sous examples/tutorials/modules/ et leurs chemins commencent par tutorials::modules. Le chemin relie le code à son rôle dans l’arborescence ; adopte une convention unique et applique-la à tous les fichiers du projet.

Le module producteur peut exposer une procédure :

space tutorials::modules::calcul;

export proc additionner(gauche: i64, droite: i64) -> i64 {
    return gauche + droite;
}

export indique que la procédure fait partie de l’interface publique. Ses paramètres et son type de retour forment un contrat pour le code appelant. La règle de calcul reste dans le module qui la possède.

Importer et appeler le module

Le fichier principal importe le chemin sous un alias, puis utilise le nom qualifié :

space tutorials::modules::main;

use tutorials::modules::calcul as calcul;

proc main() -> i64 {
    if calcul::additionner(20, 22) == 42 {
        return 0;
    }
    return 1;
}

calcul::additionner garde la provenance du nom visible. Si un autre module fournit aussi une procédure appelée additionner, le chemin indique laquelle est appelée. L’alias peut raccourcir un long chemin tout en conservant cette qualification.

Résoudre un module et exécuter le programme

La résolution doit savoir où chercher les fichiers importés. Dans l’exemple du dépôt, VITTE_MODULE_PATH=examples indique la racine appropriée :

VITTE_MODULE_PATH=examples build/bin/vitte run examples/tutorials/modules/main.vit --quiet --no-color

Résultat confirmé : code de sortie 0. Les deux sources vérifiées sont main.vit et calcul.vit. Si l’import échoue, vérifie dans cet ordre : le chemin de module déclaré, la racine de recherche, le chemin importé, puis l’export du nom utilisé.

Concevoir une interface Vitte

Avant d’exporter un nom, pose-toi ces questions :

  1. Quel autre module l’appelle réellement ?
  2. Le nom exporté décrit-il un comportement stable, ou révèle-t-il un détail de calcul ?
  3. Les paramètres et le résultat rendent-ils les obligations de l’appelant compréhensibles ?
  4. Peut-on changer l’implémentation sans modifier les appels ?

Un module qui exporte toutes ses fonctions internes rend ses choix difficiles à faire évoluer. Commence avec l’interface la plus petite utile. Ajoute un export quand un besoin concret apparaît, pas seulement parce que la déclaration existe.

Un import de module n’équivaut pas à un accès universel à ses déclarations. L’export du producteur et la résolution de l’appelant doivent tous deux convenir. Les imports globaux et certains réexports ont des limites dans les chemins de compilation ; privilégie les imports explicites déjà exercés par le dépôt.

Faire grandir l’exemple sans perdre le fil

Pour ajouter une opération, commence par écrire sa signature et son résultat attendu. Ajoute ensuite la procédure exportée dans calcul.vit, puis un appel qualifié dans main.vit. Vérifie les deux fichiers ensemble avant d’ajouter un troisième module. Cette progression permet d’attribuer plus facilement un diagnostic au chemin, à la visibilité, à la signature ou au corps.

Quand un nom de module change, recherche ses imports et actualise le chemin dans les sources et la configuration. Un chemin importé fait partie de la structure du programme : garde-le cohérent plutôt que de corriger les appels un par un au hasard.

Atelier avancé : construire un petit module de calcul

  1. Crée un module exercice::calcul contenant deux procédures publiques avec paramètres et résultats typés.
  2. Crée un fichier principal qui importe ce module sous un alias et appelle les deux opérations par leur nom qualifié.
  3. Ajoute une procédure interne sans export. Décide si elle doit rester privée et explique son rôle.
  4. Quand le programme ne résout pas le module, vérifie séparément le chemin déclaré, le chemin importé et la racine fournie au compilateur.
Correction guidée

Le module producteur porte space exercice::calcul;, déclare ses opérations avec export proc et garde ses helpers privés. Le fichier appelant déclare son propre space, écrit use exercice::calcul as calcul;, puis appelle calcul::nom(...). Le chemin de recherche doit inclure le dossier racine qui contient exercice/.
