Une expression produit une valeur

Un littéral, un nom, un appel de procédure ou une opération peut former une expression. Dans prix * quantite + frais, les multiplications et additions produisent un résultat. Dans score >= minimum, la comparaison produit un booléen. Cette idée aide à construire un programme : les expressions calculent des valeurs, puis les instructions décident quoi en faire.

proc prix_total(prix: i64, quantite: i64, livraison: i64) -> i64 {
    let sous_total: i64 = prix * quantite;
    return sous_total + livraison;
}

Calculs et priorité

Pour les calculs courants, *, / et % se font avant + et -. Les parenthèses se font d’abord. Ainsi, 2 + 3 * 4 vaut 14, tandis que (2 + 3) * 4 vaut 20. Les décalages, les opérations bit à bit, les comparaisons, les égalités et les opérateurs logiques ont eux aussi un ordre de priorité défini par la grammaire.

Tu n’as pas besoin de mémoriser toute la table pour écrire du code lisible. Dans une expression de plus de deux opérations, ajoute des parenthèses quand elles expliquent ton intention, même si la priorité du langage suffirait.

Exemple vérifié : priorité et parenthèses

examples/tutorials/expressions.vit vérifie que 2 + 3 * 4 vaut 14 et que (2 + 3) * 4 vaut 20.

build/bin/vitte run examples/tutorials/expressions.vit --quiet --no-color

Résultat confirmé : code de sortie 0 si les deux calculs donnent ces valeurs.

Comparer puis combiner

Les opérateurs == et != testent l’égalité ; <, <=, > et >= comparent un ordre. Ils donnent un bool. On combine les résultats avec and ou &&, et avec or ou ||. not ou ! inverse une condition.

proc admissible(age: i64, a_un_billet: bool) -> bool {
    return age >= 18 and a_un_billet;
}

En lecture, and signifie que les deux conditions sont requises ; or signifie qu’au moins l’une suffit. La grammaire et le compilateur définissent l’évaluation des opérateurs logiques. Quand l’ordre d’un effet de bord compte, évite de cacher un appel qui modifie l’état dans une condition composée.

Opérateurs binaires et affectations

Vitte prévoit également des opérateurs bit à bit (&, |, ^), des décalages (<<, >>) et des affectations composées dans la grammaire, comme += ou <<=. Ils sont surtout utiles quand on travaille sur des masques de bits, des drapeaux ou des représentations bas niveau. Ce sont des opérateurs distincts des mots logiques and et or.

Un opérateur reconnu par la grammaire peut ne pas être disponible dans chaque étape du compilateur. Pour le code ordinaire, commence avec l’arithmétique, les comparaisons et les booléens ; explore les opérations binaires seulement avec les exemples du dépôt et une vérification de l’outil.

Appels, accès et conversions

Après une expression, les parenthèses peuvent appeler une procédure, les crochets indexer un tableau, et le point lire un champ de forme. Les chemins qualifiés emploient ::. La grammaire prévoit aussi le point d’interrogation postfixé pour certaines expressions optionnelles ainsi que as Type pour une conversion explicite.

proc lire_tableau() -> i64 {
    let valeurs: [3]i64 = [8, 13, 21];
    return valeurs[1] + valeurs[2];
}

Cette expression fait d’abord deux accès par indice, puis une addition. Si tu dois vérifier les bornes, découpe le calcul en variables nommées et consulte les opérations de la bibliothèque adaptées au type de données.

Une méthode simple pour déboguer un calcul

  1. Repère les parenthèses déjà présentes.
  2. Note le type de chaque littéral, variable et appel.
  3. Ajoute des parenthèses temporaires pour écrire l’ordre auquel tu t’attends.
  4. Remplace les sous-expressions par des variables nommées si le calcul reste difficile à expliquer.
Lisibilité d’abord

Le meilleur calcul est celui dont une personne peut vérifier le sens sans faire une devinette sur la priorité des opérateurs.

Atelier guidé : lire une expression de gauche à droite

  1. Pour 2 + 3 * 4, ajoute les parenthèses correspondant à la priorité puis calcule le résultat.
  2. Pour (2 + 3) * 4, recalcule et explique pourquoi le résultat diffère.
  3. Écris une procédure qui renvoie vrai si un nombre est entre 10 et 20 inclus. Utilise une comparaison de chaque côté et combine-les avec and.
  4. Réécris une condition avec not et une condition inverse, puis vérifie si les deux formulations disent la même chose.
Auto-évaluation

Les deux calculs valent respectivement 14 et 20. La condition de plage est valeur >= 10 and valeur <= 20. Pour vérifier une négation, teste au moins un nombre à l’intérieur et un nombre de chaque côté.
