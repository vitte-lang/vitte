Un résultat se construit étape par étape

Une boucle n’est pas seulement une répétition. C’est un calcul découpé en états successifs. Pour la comprendre, nomme les valeurs qui changent, note leur valeur initiale, puis décris exactement ce que fait un passage.

Voici un patron d’addition sur un tableau de trois entiers :

proc somme(valeurs: [3]i64) -> i64 {
    let mut index: i64 = 0;
    let mut total: i64 = 0;

    while index < 3 {
        set total = total + valeurs[index];
        set index = index + 1;
    }

    return total;
}

À chaque passage, index désigne l’élément à ajouter ; après l’ajout, il avance d’une position. Le tableau fournit les indices 0, 1 et 2 : la condition index < 3 empêche la lecture à l’indice 3. Les tableaux fixes, l’indexation, while et set sont exercés dans le dépôt. Ce programme combiné est un patron pédagogique, pas une fixture testée telle quelle.

Écrire l’invariant avant le corps

Un invariant est une phrase qui reste vraie au début de chaque passage. Pour la somme précédente, on peut écrire :

total contient la somme des éléments déjà parcourus, de l’indice 0 jusqu’à index - 1.

Vérifie cette phrase en trois temps :

  1. Initialisation. Avant le premier passage, index vaut 0 et aucune valeur n’a été parcourue. La somme vide vaut 0 ; total est donc correct.
  2. Conservation. Si l’invariant est vrai et que index < 3, le corps ajoute exactement valeurs[index], puis avance index de 1. total correspond alors à tous les éléments parcourus.
  3. Sortie. La boucle s’arrête quand index vaut 3. Les trois éléments ont été parcourus ; l’invariant donne le résultat attendu.

Cette méthode trouve les erreurs de borne avant l’exécution. Si tu commences à 1, le premier élément manque. Si tu écris index <= 3, le programme tente de lire un quatrième élément.

Mesurer la progression

Un invariant ne suffit pas : une boucle doit aussi s’arrêter. Ici, index augmente de 1 et reste inférieur à 3 tant que le corps recommence. La distance 3 - index diminue ; elle ne peut pas diminuer indéfiniment tout en restant positive. Pour une boucle plus complexe, cherche une quantité entière qui se rapproche visiblement de zéro.

Avec continue, vérifie que le chemin qui saute le reste du corps fait tout de même progresser l’état. Avec break, précise les valeurs possibles à la sortie anticipée. Une boucle qui se termine à plusieurs endroits a plusieurs postconditions à examiner.

Tracer une boucle réelle du dépôt

Dans controle.vit, l’indice avance jusqu’à 6. L’itération 3 est ignorée avec continue ; l’itération 6 arrête la boucle avec break avant d’être ajoutée. Les valeurs ajoutées sont donc 1, 2, 4 et 5, pour un total de 12. L’exemple se lance avec :

build/bin/vitte run examples/tutorials/controle.vit --quiet --no-color

Résultat confirmé dans le dépôt : code de sortie 0. Pour voir chaque transition, fais un tableau avec les colonnes indice, branche choisie et total. Tu peux aussi comparer avec tableaux.vit, qui vérifie la lecture et l’écriture d’éléments indexés.

Un algorithme, trois preuves

Avant d’ajouter un parcours dans un programme, prépare trois réponses : pourquoi le premier indice est valide, pourquoi chaque passage garde l’indice valide, et pourquoi le dernier passage s’arrête avant la borne interdite. Cette courte preuve fait partie de la conception du programme ; elle ne dépend pas d’un message du compilateur.

Étude guidée : chercher une valeur

La recherche séquentielle visite les indices dans l’ordre jusqu’à trouver la cible ou atteindre la longueur. Voici une version pédagogique pour trois éléments :

proc contient(valeurs: [3]i64, cible: i64) -> bool {
    let mut index: i64 = 0;
    while index < 3 {
        if valeurs[index] == cible {
            return true;
        }
        set index = index + 1;
    }
    return false;
}

Avant chaque passage, l’invariant est : « aucun indice plus petit que index ne contient la cible ». Si la comparaison réussit, la procédure peut renvoyer vrai immédiatement. Sinon, augmenter l’indice étend la zone déjà examinée d’un élément. À la sortie, l’indice vaut 3 et tous les éléments ont été examinés : l’invariant permet de renvoyer faux.

Cette combinaison complète est un exemple d’étude, pas une fixture du dépôt confirmée telle quelle. Les boucles, les tableaux et les comparaisons sont présents dans des exemples exécutés ; vérifie leur combinaison exacte avant de l’utiliser comme preuve de compilation.

Éviter les bornes cachées

Dans les exemples fixes, la longueur apparaît comme un nombre tel que 3. Si tu répètes ce nombre dans plusieurs conditions, déclarations et tailles, une modification peut laisser une borne oubliée. Une constante nommée peut rendre le lien visible lorsque la prise en charge de cette constante est confirmée. Avec une taille connue au type, écris au minimum un commentaire ou un contrat expliquant pourquoi la borne de la boucle correspond au nombre d’éléments.

Les plages 0..3 sont demi-ouvertes dans les conventions documentées : elles incluent 0, 1 et 2. Mais l’opérateur de plage et for ne sont pas confirmés au runtime dans tous les cas. Pour l’exercice de preuve, le test explicite index < 3 rend les accès plus faciles à vérifier.

Étendre une trace à un cas vide

Un tableau fixe de longueur zéro n’est pas utilisé dans les fixtures de cette leçon, mais le raisonnement de boucle reste instructif : si la longueur vaut zéro, la condition de parcours est fausse avant le premier accès et la somme initialisée à zéro est renvoyée. Cette propriété s’appelle souvent le cas vide. Pour des collections réelles, vérifie que le type et le backend acceptent cette taille avant de compter dessus.

Pour une recherche, le même cas vide doit renvoyer faux sans lire de mémoire. Un invariant bien formulé te permet de vérifier ce comportement sans inventer un indice spécial.

Trace de recherche corrigée

Pour [4, 7, 2] et la cible 7 : à l’indice 0, 4 n’est pas la cible ; à l’indice 1, 7 est trouvé et la procédure renvoie vrai. Pour la cible 9, les indices 0, 1 et 2 échouent ; l’indice devient 3, la boucle s’arrête et la procédure renvoie faux.

Atelier avancé : rechercher une valeur

  1. Trace le calcul de somme sur le tableau [4, 7, 2]. Note index et total avant et après chaque passage.
  2. Remplace la condition index < 3 par index <= 3. À quel passage l’accès devient-il invalide ? Répare la condition.
  3. Adapte le raisonnement pour chercher la première occurrence de 7. Écris l’invariant en français avant d’introduire une condition de sortie anticipée.
  4. Compare ta trace à la fixture controle.vit. Explique pourquoi la valeur 3 ne participe pas au total et pourquoi l’indice 6 n’y participe pas non plus.
Correction détaillée

Pour la somme de [4, 7, 2], les états au début des passages sont (0,0), (1,4) et (2,11). Après le dernier ajout, l’état devient (3,13) ; 3 < 3 est faux et aucun accès à l’indice 3 n’a lieu. Avec index <= 3, le corps s’exécuterait une quatrième fois et l’accès sortirait du tableau.

Pour rechercher 7, l’invariant dit qu’aucune position plus petite que l’indice courant n’a encore contenu la cible. À l’indice 0 la valeur est 4 ; à l’indice 1, la comparaison réussit. Pour chercher 9, les trois éléments sont examinés, l’indice devient 3 et le résultat est faux.

Dans controle.vit, l’indice 3 passe par continue, tandis que l’indice 6 passe par break avant l’addition. Les valeurs ajoutées sont 1, 2, 4 et 5 : le total vaut 12.
