Pour manipuler une séquence ou laisser une procédure consulter un objet, Vitte fournit des tableaux, des références et des pointeurs. takeaway: Choisis la représentation la plus simple qui exprime le contrat attendu ; un pointeur brut demande une prudence particulière. practice: Parcours un tableau avec une plage d’indices et vérifie que ton code traite correctement le premier et le dernier élément. ---

Tableaux de taille connue

Le type [N]T décrit un tableau de N éléments de type T. Par exemple, [3]i64 contient trois entiers signés de 64 bits. On peut écrire la valeur avec une liste littérale puis lire un élément avec un indice entre crochets :

proc deuxieme() -> i64 {
    let notes: [3]i64 = [14, 17, 19];
    return notes[1];
}

Les indices commencent à zéro dans les exemples Vitte : notes[0] est le premier élément et notes[2] le troisième. L’accès notes[3] dépasse la longueur de ce tableau ; considère les limites comme une condition à vérifier, pas comme une convention facultative.

Exemple vérifié : tableau fixe, lecture et écriture

examples/tutorials/tableaux.vit remplace le deuxième élément puis vérifie que la somme vaut 42.

build/bin/vitte run examples/tutorials/tableaux.vit --quiet --no-color

Résultat confirmé avec le frontend natif : code de sortie 0.

La bibliothèque core fournit également des opérations sur des tableaux et des tranches. Les fonctions de tranches attendent une vue empruntée sur une séquence existante au lieu d’allouer une nouvelle collection. Les détails de durée de vie et les opérations disponibles sont documentés dans les modules concernés.

Références : emprunter une valeur

Le type &T représente une référence vers une valeur de type T. La notation &valeur demande une référence à une expression, et un paramètre de type &Point permet d’inspecter un point existant. Le préfixe mut apparaît dans des types comme &mut T lorsque le contrat autorise une modification à travers la référence.

proc somme(valeurs: &[3]i64) -> i64 {
    return valeurs[0] + valeurs[1] + valeurs[2];
}

proc modifier(premier: &mut i64) {
    set *premier = *premier + 1;
}

Les références expriment un accès à des données qui appartiennent ailleurs. Il est utile de les apprendre en séparant deux questions : qui possède la donnée et qui a le droit de la lire ou la changer ? Le compilateur Vitte et ses bibliothèques évoluent encore ; vérifie quelles règles de durée de vie et de mutabilité sont appliquées par la version que tu utilises.

Références : chemin compilateur testé

examples/tutorials/references.vit vérifie qu’une procédure reçoit un point par référence et calcule 42 avec build/bin/vitte-bootstrap run examples/tutorials/references.vit --quiet --no-color (code de sortie 0). Le frontend natif rejette actuellement ce même cas à l’abaissement HIR (E1011).

Pointeurs : une abstraction plus basse

Un type *T est un pointeur vers T. Les pointeurs apparaissent dans les interfaces système, l’interopérabilité et les bibliothèques qui contrôlent directement les adresses mémoire. L’expression *pointeur déréférence un pointeur. Une adresse incorrecte, désalignée ou déjà invalidée peut rendre le programme dangereux ; la syntaxe seule ne rend pas l’opération sûre.

La grammaire prévoit des blocs unsafe { ... } afin de rendre explicites certaines opérations qui demandent des garanties supplémentaires. Un bloc unsafe ne corrige pas l’adresse et ne prouve pas que l’objet existe : il marque un endroit où la personne qui écrit le programme prend la responsabilité de respecter les invariants mémoire.

Repère de prudence

N’utilise pas un pointeur brut pour remplacer une référence ou un tableau lorsqu’ils expriment déjà ton besoin. Le code bas niveau doit préciser la durée de vie, l’alignement, la taille de la zone et les règles d’alias qu’il suppose.

Valeurs optionnelles et absence

La bibliothèque fondamentale emploie le type nullable ?T : il contient soit une valeur de type T, soit null. L’alias générique Option<T> désigne cette représentation dans le module core::types::option. Avant de lire la valeur, teste qu’elle n’est pas null.

proc valeur_ou_zero(valeur: ?i64) -> i64 {
    if valeur != null {
        return valeur;
    }
    return 0;
}

Une option représente l’absence comme une donnée, plutôt que d’inventer une valeur spéciale comme zéro qui pourrait également être un résultat légitime. La représentation nullable ne distingue pas « option absente » et « option présente avec une valeur elle-même nulle » si le type contenu accepte aussi null.

La grammaire prévoit aussi un point d’interrogation postfixé sur certaines expressions. Ne déduis pas son comportement à partir du symbole seul : vérifie sa sémantique dans la documentation de l’outil et dans les exemples de la bibliothèque installée.

L’opérateur ?? représente une autre idée : choisir une valeur de repli lorsque la partie gauche est absente. On peut lire age ?? 0 comme « utilise l’âge s’il existe, sinon zéro ». C’est utile quand le repli a réellement du sens dans le domaine ; sinon, traite l’absence comme un cas distinct au lieu de la masquer.

Pointeurs et valeurs nullable

Les extraits de pointeurs, ?T, ? et ?? sur cette page sont explicatifs : les suites exécutées pour le site n’ont pas confirmé un programme complet avec ces constructions. Le tableau fixe et la référence ci-dessus ont des commandes et des résultats testés.

Penser aux frontières

Les bugs mémoire se cachent souvent sur les limites : tableau vide, indice égal à la longueur, référence conservée après la durée de vie de la valeur, ou pointeur converti vers un type plus étroit. Décris le contrat d’une procédure qui reçoit une zone mémoire : combien d’éléments sont accessibles, qui peut les modifier et qui garde la propriété de la zone ?

Garde un invariant lisible

Quand tu touches à la mémoire directement, écris les conditions requises près de l’opération. Une personne qui relit le code doit pouvoir vérifier la taille, la validité et l’alignement avant de suivre la déréférence.

La longueur d’un tableau appartient à son type

Avec [3]i64, la longueur est connue : le tableau contient exactement trois valeurs de type i64. Les indices valides sont 0, 1 et 2. L’indice 3 est déjà hors de la plage, même s’il ressemble à une position « après le dernier élément ».

Pour parcourir les éléments avec un while confirmé, maintiens un indice mutable et teste-le avant l’accès :

let mut index: i64 = 0;
while index < 3 {
    let valeur: i64 = notes[index];
    set index = index + 1;
}

Ce fragment illustre l’ordre indispensable : tester la borne, lire la case, puis faire progresser l’indice. Le parcours for sur tableau n’est pas confirmé au backend dans l’audit ; ne le substitue pas silencieusement à cette forme lorsque tu veux un exemple exécutable avec le frontend natif.

Choisir entre un tableau, une référence et un pointeur

Ces formes ne répondent pas à la même question. Un tableau fixe exprime une séquence dont la taille est connue. Une référence exprime un accès à une valeur existante sans écrire directement une adresse. Un pointeur brut donne accès à une adresse et demande que le programme établisse lui-même davantage de garanties.

Pour chaque paramètre de données, précise qui garde la valeur, qui peut la lire, qui peut la modifier et combien de temps l’accès reste valide. Le type &T et le type &mut T signalent une différence de contrat d’accès, mais la présence de ces formes ne prouve pas à elle seule que le compilateur vérifie toutes les règles de durée de vie ou d’alias attendues.

Absence : garder la distinction avec une valeur normale

Une valeur nullable de forme ?T peut représenter une donnée présente ou null. Si zéro est une valeur autorisée pour T, elle ne doit pas servir de code implicite pour l’absence : zéro et null expriment deux situations différentes.

Une valeur de repli, telle que age ?? 0, simplifie le calcul seulement si zéro est réellement le comportement voulu lorsque l’âge manque. Si l’absence change la décision à prendre, conserve-la comme cas distinct et traite-la explicitement. La syntaxe nullable et les opérateurs associés ne sont pas tous prouvés en compilation/exécution dans le backend audité.

Contrat mental avant une lecture mémoire

Avant une lecture indexée, vérifie l’intervalle ; avant une écriture, vérifie également que le propriétaire autorise la modification ; avant une déréférence, vérifie la validité de l’adresse, l’alignement, la taille accessible et la durée de vie. Pour un tableau fixe, ces questions se ramènent principalement à la borne de l’indice. Pour un pointeur, elles deviennent des obligations explicites de la procédure qui le reçoit.

Correction du parcours sûr

Pour un tableau de longueur 3, commence à l’indice 0, continue tant que l’indice est strictement inférieur à 3 et n’accède qu’après le test. La progression doit augmenter l’indice exactement une fois par passage. Le dernier accès a lieu à l’indice 2.

Atelier guidé : borner un accès

  1. Crée un tableau de trois entiers et écris une procédure qui renvoie la somme de ses éléments avec trois indices explicites.
  2. Réécris le calcul avec une boucle sur 0..3. Compare la version la plus facile à modifier si le tableau passe à quatre éléments.
  3. Donne un tableau à une procédure par référence en lecture. Explique qui garde la donnée et ce que la procédure est autorisée à faire.
  4. Pour un pointeur imaginaire vers le premier élément, écris les invariants à vérifier avant de le déréférencer. Ne tente pas d’utiliser une adresse arbitraire.
Corrigé détaillé de l’atelier

Pour un tableau de trois nombres, les indices valides sont 0, 1 et 2. L’accès au premier, au milieu et au dernier élément est donc respectivement valeurs[0], valeurs[1] et valeurs[2]. Une boucle while index < 3 teste l’indice avant la lecture et l’incrémente une fois après le travail.

La version avec trois accès explicites est facile à lire pour une taille fixe ; la boucle évite de recopier les opérations quand la taille change. L’expression for index in 0..3 peut exprimer l’intention, mais son exécution dans le backend natif n’est pas confirmée par l’audit du dépôt.

Une référence permet à une procédure d’accéder à une valeur existante selon le contrat de la référence. Un pointeur demande des garanties supplémentaires : adresse valide, alignement, zone assez grande, absence de conflit de mutation et durée de vie suffisante. Si tu ne peux pas expliquer chacune de ces conditions, reste sur le tableau ou la référence vérifiée.
