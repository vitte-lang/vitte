Choisir avec if

Une condition if exécute un bloc si son expression booléenne est vraie. else donne le chemin alternatif ; elif ajoute un autre test dans la même décision.

proc categorie(age: i64) -> i64 {
    if age < 0 {
        return -1;
    } elif age < 18 {
        return 0;
    } else {
        return 1;
    }
}

Lis les branches dans l’ordre. La première condition vraie choisit un chemin, donc place les tests spécifiques avant les cas plus généraux. Chaque branche ici renvoie aussitôt une valeur : on voit clairement qu’aucun cas ne doit se poursuivre vers les lignes suivantes.

Répéter avec while

Une boucle while vérifie sa condition avant chaque passage. Son corps doit normalement faire évoluer une donnée qui rapproche le programme de l’arrêt.

proc somme_de_un_a_cinq() -> i64 {
    let mut indice: i64 = 1;
    let mut total: i64 = 0;

    while indice <= 5 {
        set total = total + indice;
        set indice = indice + 1;
    }

    return total;
}

On commence avec indice = 1. À chaque passage, on ajoute l’indice au total et on l’augmente. Après le passage où l’indice vaut 5, il devient 6 ; la condition indice <= 5 est alors fausse et la procédure renvoie 15. Sans l’incrément, le programme resterait dans la boucle indéfiniment.

Exemple vérifié : while, continue et break

examples/tutorials/controle.vit saute l’indice 3, s’arrête à 6 et vérifie que le total est 12.

build/bin/vitte run examples/tutorials/controle.vit --quiet --no-color

Résultat confirmé : code de sortie 0.

Répétition ouverte et sortie anticipée

La grammaire prévoit aussi loop { ... }, une boucle sans condition placée en tête. Elle se termine généralement par break; lorsqu’un cas d’arrêt est atteint. continue; saute au début du prochain passage. Ces sauts peuvent être utiles, mais si plusieurs points quittent le corps, vérifie que le flot de contrôle reste facile à suivre.

proc chercher_valeur() -> i64 {
    let mut essai: i64 = 0;
    loop {
        if essai == 7 {
            break;
        }
        set essai = essai + 1;
    }
    return essai;
}

Parcourir avec for

La forme for nom in expression { ... } exprime un parcours. Selon les types d’itérables et la bibliothèque disponibles, l’expression peut être une plage ou une séquence. L’exemple suivant montre l’intention d’une plage d’indices ; vérifie la prise en charge de l’itération dans la version du compilateur que tu utilises.

proc additionner_cinq(valeurs: [5]i64) -> i64 {
    let mut total: i64 = 0;
    for index in 0..5 {
        set total = total + valeurs[index];
    }
    return total;
}

La plage 0..5 contient les indices 0 à 4 : la borne finale est exclue. Cette convention est pratique pour parcourir un tableau de cinq éléments. Un parcours par plage est utile quand tu as besoin de l’indice ; si une collection fournit un itérateur et que ton code n’a pas besoin de position, l’itérateur peut exprimer l’intention plus directement.

État de vérification de for

Les tests du dépôt n’ont pas confirmé l’exécution de la forme for sur plage. Le test ciblé d’un for sur tableau atteint puis échoue au backend. Pour un parcours exécutable avec le compilateur natif audité, utilise l’exemple while ci-dessus.

Choisir un cas avec match

match associe une expression à plusieurs bras. Dans la grammaire, chaque bras utilise => et se termine par une virgule. Avec une énumération déclarée par pick, cette forme rend les différents états visibles ensemble. La couverture d’exhaustivité dépend de l’analyseur et du compilateur ; traite chaque cas important explicitement.

pick Etat {
    Inactif,
    Pret,
    Termine,
}

proc code_etat(etat: Etat) -> i64 {
    match etat {
        Etat.Inactif => { return 0; },
        Etat.Pret => { return 1; },
        Etat.Termine => { return 2; },
    }
    return -1;
}

Pour les erreurs de compilation liées à une branche, commence par vérifier le type de l’expression examinée, puis la syntaxe de chaque bras et ses séparateurs.

Trois questions pour une boucle sûre

  1. Quelle valeur change à chaque passage ?
  2. Quelle condition finit par devenir fausse ou déclenche break ?
  3. Que se passe-t-il aux limites : zéro élément, un seul élément, ou valeur maximale ?
Trace sur papier

Pour une boucle nouvelle, écris quelques lignes avec l’indice, l’état et le total. Cette petite table révèle vite une borne décalée ou une mise à jour oubliée.

Atelier guidé : parcours, arrêt et limites

  1. Trace la boucle de somme de 1 à 5. Fais une ligne avant la boucle, une par passage et une après sa sortie.
  2. Change indice <= 5 en indice < 5. Quel nombre manque-t-il ? Modifie ensuite l’initialisation et explique pourquoi les deux changements interagissent.
  3. Écris une procédure qui parcourt un tableau de trois valeurs avec for index in 0..3. Vérifie que la dernière lecture est à l’indice 2.
  4. Ajoute un cas à match. Vérifie ce qui se passe si tu oublies de traiter une variante dans la version du compilateur que tu utilises.
Auto-évaluation

Une boucle sûre a un état qui progresse, une condition d’arrêt atteignable et des accès compatibles avec les bornes. Les plages Vitte des exemples de bibliothèque sont demi-ouvertes : 0..3 contient 0, 1 et 2.
