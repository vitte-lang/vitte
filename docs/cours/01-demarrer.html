Notre premier programme

Voici le petit programme de départ fourni dans le dépôt. Il affiche un message et annonce au système qu’il s’est terminé sans erreur :

space examples/hello;

proc main() -> int {
    print("Hello from Vitte!");
    return 0;
}

Prends une minute pour le regarder sans chercher à tout mémoriser. On va le lire de haut en bas, comme on lirait une recette.

La ligne space donne un nom au module

space examples/hello; déclare l’espace de noms auquel appartient ce fichier. Le chemin est formé de segments ; la grammaire accepte les séparateurs / ou :: selon l’endroit où tu l’écris. Dans un petit exercice, il sert surtout à éviter les noms vagues ; dans un vrai projet, il aide à organiser les modules. Le point-virgule termine cette déclaration.

proc introduit une procédure

Une procédure est un morceau de programme qu’on peut appeler par son nom. main est ici le point d’entrée conventionnel : quand le programme est lancé, l’environnement cherche cette procédure. Les parenthèses sont vides parce que cette première version ne reçoit aucune information. La flèche -> int annonce le type de la valeur renvoyée. Les accolades délimitent le corps.

À l’intérieur, print(...) est un appel. On donne à la procédure print un texte entre guillemets. La ligne finit par un point-virgule. Enfin, return 0; renvoie le nombre zéro : par convention, cette valeur signifie que tout s’est bien passé.

Quel compilateur vérifie cet exemple ?

Dans le dépôt audité, print fonctionne avec le compilateur bootstrap, mais build/bin/vitte (frontend natif) le signale comme nom inconnu. La commande confirmée pour ce fichier utilise donc explicitement build/bin/vitte-bootstrap. Voir aussi l’état du support.

Installer et vérifier l’outil

Dans ce dépôt, la compilation du compilateur se lance avec make. Une fois le binaire disponible dans ton environnement, vérifie son installation :

make
make build/bin/vitte-bootstrap
build/bin/vitte-bootstrap run examples/hello.vit --quiet --no-color

make construit le binaire natif principal. La seconde commande construit aussi le compilateur bootstrap, qui est le chemin vérifié pour ce premier exemple. Le programme écrit Hello from Vitte! et se termine avec le code 0.

Les commandes à connaître

  • build/bin/vitte check fichier.vit vérifie le sous-ensemble du frontend natif.
  • build/bin/vitte lex fichier.vit affiche les tokens du fichier.
  • build/bin/vitte parse fichier.vit demande au parseur de reconnaître les formes syntaxiques.
  • build/bin/vitte run fichier.vit compile et exécute les constructions prises en charge ; les chapitres suivants donnent des cas réellement confirmés.
Un repère important

Un message disant que le texte est bien analysé ne garantit pas à lui seul que le programme complet pourra être compilé ou exécuté. Dans ce cours, on distinguera donc toujours la syntaxe du langage et les capacités actuelles de l’outil.

Comment travailler pendant le cours

Crée un dossier pour tes exercices et garde un fichier par expérience. Avant de lancer une commande, essaie de prédire ce que le compilateur va accepter et ce que le programme devrait renvoyer. Cette prédiction te donne une question précise à vérifier.

Quand tu rencontres une erreur, commence par lire le premier diagnostic, sa ligne et le nom de la construction concernée. Corrige une chose à la fois. Une erreur de syntaxe empêche parfois les vérifications suivantes ; il est donc normal qu’une modification fasse disparaître plusieurs messages d’un seul coup.

La suite reprend le même exemple en observant la ponctuation, les commentaires et les blocs. Tu sauras ainsi lire les petits détails qui rendent un programme Vitte compréhensible à la machine.

Lire le programme comme une suite de décisions

Relis maintenant le fichier en posant une question à chaque ligne : « qu’est-ce que cette ligne apporte au reste du programme ? » space fixe le contexte du fichier. proc main déclare le point de départ. Le type int précise la forme de la réponse finale. L’appel à print produit l’affichage. Enfin, return 0 termine cette exécution avec un code que le système peut interpréter.

Il faut distinguer trois choses que l’on confond facilement au début :

  • Le texte source est ce que tu écris dans le fichier.
  • Le programme compilé est le résultat produit par l’outil pour une cible donnée.
  • Le résultat d’exécution est ce que le programme affiche et le code avec lequel il termine.

Quand le fichier ne fonctionne pas, détermine d’abord à quelle étape le problème apparaît. Une accolade oubliée concerne la lecture de la syntaxe ; une commande inconnue concerne la compilation ou la bibliothèque ; un texte différent de celui attendu concerne le comportement une fois le programme lancé.

Suivre l’exemple du fichier jusqu’au résultat

Depuis la racine du dépôt, les commandes du cours sont :

make build/bin/vitte-bootstrap
build/bin/vitte-bootstrap parse examples/hello.vit
build/bin/vitte-bootstrap run examples/hello.vit --quiet --no-color

La première prépare l’outil bootstrap utilisé pour cet exemple. La deuxième demande seulement au parseur de reconnaître la structure. La troisième compile puis exécute le programme. Le résultat attendu est le texte Hello from Vitte! et le code de sortie 0. Un code de sortie différent de zéro ne signifie pas nécessairement que la syntaxe est incorrecte : il signifie que le programme lancé a renvoyé une autre valeur.

Le binaire natif build/bin/vitte est une autre voie de compilation. Pour cette leçon, ne remplace pas automatiquement le binaire indiqué par celui-ci : le dépôt audité rejette l’appel à print dans ce cas. La page sur le support explique les différences entre ces voies.

Ta première méthode de dépannage

  1. Vérifie que tu es à la racine du dépôt : le chemin examples/hello.vit doit exister depuis cet endroit.
  2. Vérifie le nom du binaire, le sous-commande et le chemin du fichier.
  3. Lis la première erreur complète, surtout le code, le fichier et la ligne.
  4. Ne modifie qu’un élément, puis relance la même commande.
  5. Quand le résultat est correct, note la commande exacte ; elle devient une preuve que tu peux reproduire.
Point de contrôle

Tu peux passer à la suite lorsque tu sais relancer l’exemple, expliquer la valeur de retour et distinguer un échec d’analyse d’un code de sortie non nul.

Atelier guidé : ton premier fichier

  1. Depuis la racine du dépôt, lance build/bin/vitte-bootstrap run examples/hello.vit --quiet --no-color et observe le message ainsi que le code de sortie.
  2. Change le texte de l’appel à print, puis relance cette même commande. Vérifie que le texte affiché change.
  3. Change le retour de 0 à 1. Explique pourquoi l’outil peut accepter la syntaxe même si le code de sortie indique une erreur aux scripts qui lanceront ton programme.
  4. Retire une accolade, lance build/bin/vitte-bootstrap parse examples/hello.vit, puis restaure-la. Note le numéro de ligne indiqué par le diagnostic.
Corrigé commenté et critères de réussite

space examples/hello; place le fichier dans un chemin de module. proc main() déclare le point d’entrée sans paramètres. -> int annonce la valeur de fin ; les accolades délimitent son corps. print est un appel de procédure. return 0 rend zéro au système.

Après avoir changé le texte, la sortie attendue suit la nouvelle chaîne. Après avoir changé le retour en 1, le programme peut encore être syntaxiquement valide, mais un outil ou un script qui interprète les codes de sortie voit une fin différente. Après avoir retiré une accolade, parse doit signaler une structure incomplète ou mal formée ; le numéro de ligne peut indiquer l’endroit où l’absence devient visible, pas toujours l’endroit où l’accolade a été supprimée.

Tu as réussi si tu peux refaire ces prédictions avant de lancer la commande et expliquer pourquoi cet exemple utilise vitte-bootstrap.
