Regrouper des champs avec form

Une forme déclare un type composé. Elle rassemble plusieurs champs sous un seul nom :

form Point {
    x: i64,
    y: i64,
}

proc distance_manhattan(point: Point) -> i64 {
    return point.x + point.y;
}

Le type Point évite de transporter séparément une coordonnée horizontale et une coordonnée verticale. Les noms des champs documentent leur rôle. Le corps peut y accéder avec la notation pointée, par exemple point.x.

On construit une valeur de forme en donnant les champs par leur nom :

proc exemple() -> i64 {
    let point: Point = Point {
        x: 12,
        y: 8,
    };
    return distance_manhattan(point);
}

Cette construction rend l’ordre des données sans importance pour le lecteur et évite les appels remplis de nombres sans étiquette. Pour une forme imbriquée, un champ peut lui-même recevoir une valeur construite d’un autre type.

Les formes gardent ensemble des données cohérentes

Imagine un rectangle défini par un coin minimum et un coin maximum. Deux champs de type Point expriment directement le modèle :

form Rectangle {
    minimum: Point,
    maximum: Point,
}

proc largeur(rectangle: Rectangle) -> i64 {
    return rectangle.maximum.x - rectangle.minimum.x;
}

Quand plusieurs procédures reçoivent les mêmes groupes de paramètres, c’est souvent le signe qu’une forme pourrait donner un nom à ce groupe. Mais n’ajoute pas un nouveau type juste pour envelopper une valeur sans règle ni sens supplémentaire : un nom utile exprime une idée du domaine.

Représenter des états avec pick

Une déclaration pick énumère des variantes possibles. Choisir entre ces variantes signifie qu’une valeur est dans un état parmi plusieurs :

pick Etat {
    Nouveau,
    EnCours,
    Termine,
}

proc est_actif(etat: Etat) -> bool {
    return etat == Etat.EnCours;
}

Une variante peut également porter des types dans ses parenthèses selon la grammaire, comme Erreur(i64). Cette forme suggère qu’une variante peut contenir une information associée. Avant de baser un programme sur une variante porteuse de données, vérifie les constructions et les accès réellement pris en charge dans le compilateur utilisé.

Exemple vérifié : champs de forme et charge utile de pick

examples/tutorials/formes-choix.vit additionne les champs d’un point et extrait le nombre porté par la variante Ok.

build/bin/vitte run examples/tutorials/formes-choix.vit --quiet --no-color

Résultat confirmé avec le frontend natif : code de sortie 0.

Choisir entre une forme et un choix

Pose-toi la question suivante : est-ce que mon objet possède plusieurs propriétés en même temps, ou est-il dans un état parmi plusieurs ? Un compte a probablement un identifiant, un nom et un solde à la fois : c’est une bonne candidate pour une form. Une opération est soit en attente, soit réussie, soit échouée : c’est souvent un pick.

Un état explicite empêche des combinaisons invalides. Trois booléens séparés peuvent produire huit combinaisons, dont beaucoup n’ont aucun sens ; trois variantes bien nommées décrivent directement les cas autorisés.

Immutabilité et mise à jour

Un champ lu à travers une valeur ne signifie pas automatiquement que toute la forme peut être modifiée. La variable locale qui contient la forme doit elle-même être mutable pour les affectations acceptées par le langage, et l’analyseur doit autoriser la cible de l’affectation. Garde des mises à jour explicites et utilise des procédures de transformation quand tu veux rendre un changement facile à vérifier.

Construis des noms parlants

Si un type se décrit facilement en une phrase avec ses champs, son nom clarifiera les signatures de toutes les procédures qui l’utilisent.

Atelier guidé : dessiner un modèle avant de coder

  1. Sur papier, liste les informations d’un livre : titre, nombre de pages et disponibilité. Crée une form Livre avec des champs typés.
  2. Écris une procédure qui reçoit &Livre et décide si le livre est long. Elle ne doit pas modifier le livre.
  3. Modélise un statut d’emprunt avec pick : disponible, prêté, en réparation. Écris une condition distincte pour chaque variante.
  4. Imagine quelles combinaisons seraient possibles si tu utilisais trois booléens. Compare-les aux variantes du choix nommé.
Auto-évaluation

La forme convient aux propriétés qui coexistent. Le choix convient aux états exclusifs. Si ton modèle permet une combinaison qui n’a pas de sens dans le domaine, rends cette combinaison impossible avec une variante nommée.
