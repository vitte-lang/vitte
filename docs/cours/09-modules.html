--- title: Modules, imports et exports permalink: /cours/09-modules/ chapter: 9 duration: 35 minutes lead: Un programme grandit en plusieurs fichiers. Les modules donnent une adresse logique à chaque fichier, tandis que les imports et exports définissent comment les morceaux se parlent. takeaway: Un nom qualifié dit d’où vient une déclaration ; une interface exportée indique ce qu’un autre module peut utiliser. practice: Sépare une procédure de calcul dans un module, exporte-la, puis importe le module depuis un fichier appelant. ---

Un module a un chemin

Une déclaration space donne au fichier un chemin de module. Le dépôt montre souvent le chemin correspondant à l’arborescence, avec des barres obliques, et les imports utilisent des segments séparés par ::. Les deux graphies sont prévues par la grammaire pour les chemins.

space outils::calcul;

export proc doubler(valeur: i64) -> i64 {
    return valeur * 2;
}

Garde le chemin logique du module cohérent avec sa place dans le projet. Quand tu reçois une erreur « module introuvable », vérifie le chemin déclaré, le chemin d’import et la racine de recherche configurée par l’outil.

Importer un nom

use rend une déclaration ou un module accessible au fichier courant. Le chemin complet garde la provenance visible. as donne un alias local plus court :

use outils::calcul as calcul;

proc resultat() -> i64 {
    return calcul::doubler(21);
}

La grammaire prévoit également des imports nommés par groupe, par exemple use core::types::option::{Option, option_some};, ainsi que les imports globaux. Un import ciblé est généralement plus facile à lire : on sait d’où vient chaque nom et on limite les collisions.

Exporter une interface publique

Une déclaration peut être rendue visible depuis un autre module avec un modificateur de visibilité, comme export. On peut exporter une procédure, une constante, une forme ou un choix. Le module conserve ainsi ses détails internes tout en publiant les points d’entrée nécessaires.

space outils::prix;

const TAUX: i64 = 20;

export proc avec_taxe(prix: i64) -> i64 {
    return prix + (prix * TAUX / 100);
}

Le nom TAUX reste privé dans cet exemple, tandis que avec_taxe est exporté. Une interface publique stable permet de réorganiser les détails internes sans demander aux appelants de changer. La grammaire accepte aussi des listes d’exports et l’export d’un module entier ; les règles de réexport ne sont pas toutes prises en charge dans chaque profil de compilation.

Conflits de noms et visibilité

Deux modules peuvent publier le même nom. En conservant les noms qualifiés, on distingue comptes::Point de dessin::Point. Les imports globaux rendent les collisions plus probables et cachent la provenance d’un nom. Utilise des alias explicites si deux noms se ressemblent.

Il faut aussi distinguer un module importé de ses membres visibles. Importer un module ne doit pas automatiquement donner accès à ses déclarations privées. Si un appel qualifié échoue, vérifie que le nom est bien exporté et qu’il n’y a pas de faute dans un segment du chemin.

Un exemple à deux fichiers

Dans calcul.vit, déclare un chemin de module et exporte une procédure additionner. Dans main.vit, importe le module sous un alias puis appelle cette procédure. Les deux fichiers confirmés se trouvent dans examples/tutorials/modules/.

Le résolveur de modules cherche les sources selon ses chemins configurés et met en cache des résolutions. Pour un programme de production, documente la racine du projet et les conventions de modules au lieu de dépendre d’un chemin local implicite.

Exemple vérifié : import, alias et appel qualifié

Depuis la racine du dépôt, la variable VITTE_MODULE_PATH=examples ajoute le dossier qui contient les sources importées.

VITTE_MODULE_PATH=examples build/bin/vitte run examples/tutorials/modules/main.vit --quiet --no-color

Les sources sont main.vit et calcul.vit. Résultat confirmé : code de sortie 0.

Une interface est une promesse

Avant d’exporter un nom, demande-toi si les autres modules ont vraiment besoin de le connaître. Moins l’interface publique expose de détails, plus le module peut évoluer sereinement.

Atelier guidé : deux fichiers, un contrat

  1. Crée calcul.vit et déclare le module exercice::calcul. Exporte deux procédures : addition et multiplication.
  2. Crée main.vit dans un module distinct et importe exercice::calcul.
  3. Appelle les deux procédures via leur chemin qualifié et vérifie les résultats attendus avec des assertions ou un point de retour simple.
  4. Rends une troisième procédure privée. Tente de l’appeler depuis main, lis le diagnostic, puis décide si elle doit réellement faire partie de l’interface.
Auto-évaluation

Le module producteur déclare les opérations et leur visibilité ; le module appelant dépend uniquement des noms exportés. Le chemin qualifié montre la provenance et réduit l’ambiguïté quand deux modules utilisent le même nom.
