Les modules donnent une adresse logique à chaque fichier, tandis que les imports et exports définissent comment les morceaux se parlent. takeaway: Un nom qualifié dit d’où vient une déclaration ; une interface exportée indique ce qu’un autre module peut utiliser. practice: Sépare une procédure de calcul dans un module, exporte-la, puis importe le module depuis un fichier appelant. ---

Un module a un chemin

Une déclaration space donne au fichier un chemin de module. Le dépôt montre souvent le chemin correspondant à l’arborescence, avec des barres obliques, et les imports utilisent des segments séparés par ::. Les deux graphies sont prévues par la grammaire pour les chemins.

space outils::calcul;

export proc doubler(valeur: i64) -> i64 {
    return valeur * 2;
}

Garde le chemin logique du module cohérent avec sa place dans le projet. Quand tu reçois une erreur « module introuvable », vérifie le chemin déclaré, le chemin d’import et la racine de recherche configurée par l’outil.

Importer un nom

use rend une déclaration ou un module accessible au fichier courant. Le chemin complet garde la provenance visible. as donne un alias local plus court :

use outils::calcul as calcul;

proc resultat() -> i64 {
    return calcul::doubler(21);
}

La grammaire prévoit également des imports nommés par groupe, par exemple use core::types::option::{Option, option_some};, ainsi que les imports globaux. Un import ciblé est généralement plus facile à lire : on sait d’où vient chaque nom et on limite les collisions.

Exporter une interface publique

Une déclaration peut être rendue visible depuis un autre module avec un modificateur de visibilité, comme export. On peut exporter une procédure, une constante, une forme ou un choix. Le module conserve ainsi ses détails internes tout en publiant les points d’entrée nécessaires.

space outils::prix;

const TAUX: i64 = 20;

export proc avec_taxe(prix: i64) -> i64 {
    return prix + (prix * TAUX / 100);
}

Le nom TAUX reste privé dans cet exemple, tandis que avec_taxe est exporté. Une interface publique stable permet de réorganiser les détails internes sans demander aux appelants de changer. La grammaire accepte aussi des listes d’exports et l’export d’un module entier ; les règles de réexport ne sont pas toutes prises en charge dans chaque profil de compilation.

Conflits de noms et visibilité

Deux modules peuvent publier le même nom. En conservant les noms qualifiés, on distingue comptes::Point de dessin::Point. Les imports globaux rendent les collisions plus probables et cachent la provenance d’un nom. Utilise des alias explicites si deux noms se ressemblent.

Il faut aussi distinguer un module importé de ses membres visibles. Importer un module ne doit pas automatiquement donner accès à ses déclarations privées. Si un appel qualifié échoue, vérifie que le nom est bien exporté et qu’il n’y a pas de faute dans un segment du chemin.

Un exemple à deux fichiers

Dans calcul.vit, déclare un chemin de module et exporte une procédure additionner. Dans main.vit, importe le module sous un alias puis appelle cette procédure. Les deux fichiers confirmés se trouvent dans examples/tutorials/modules/.

Le résolveur de modules cherche les sources selon ses chemins configurés et met en cache des résolutions. Pour un programme de production, documente la racine du projet et les conventions de modules au lieu de dépendre d’un chemin local implicite.

Exemple vérifié : import, alias et appel qualifié

Depuis la racine du dépôt, la variable VITTE_MODULE_PATH=examples ajoute le dossier qui contient les sources importées.

VITTE_MODULE_PATH=examples build/bin/vitte run examples/tutorials/modules/main.vit --quiet --no-color

Les sources sont main.vit et calcul.vit. Résultat confirmé : code de sortie 0.

Une interface est une promesse

Avant d’exporter un nom, demande-toi si les autres modules ont vraiment besoin de le connaître. Moins l’interface publique expose de détails, plus le module peut évoluer sereinement.

Tracer la résolution d’un import

Pour comprendre un import, écris son chemin segment par segment. Dans use tutorials::modules::calcul as calcul;, le résolveur doit trouver le module tutorials, puis son enfant modules, puis la déclaration calcul. L’alias final calcul est le nom local à utiliser dans le fichier courant.

Une erreur de chemin se diagnostique plus facilement si tu vérifies ces éléments séparément :

  1. La racine fournie au programme contient-elle le premier segment du chemin ?
  2. Le fichier source déclare-t-il le chemin logique attendu par son appelant ?
  3. Le nom final correspond-il à une procédure, un type ou un module réellement déclaré ?
  4. La déclaration est-elle exportée si elle est appelée depuis un autre module ?
  5. L’appel utilise-t-il le nom qualifié exact, avec les segments et l’alias attendus ?

La commande vérifiée de l’exemple donne une racine explicite avec VITTE_MODULE_PATH=examples. Si l’on omet cette racine, la source principale existe toujours mais le compilateur peut ne pas retrouver la source importée. Cela montre pourquoi un échec de résolution n’est pas nécessairement une erreur dans la procédure importée.

Découper les responsabilités d’un petit projet

Un bon découpage suit les raisons de changer le code. Le module de calcul possède les règles numériques. Un module de modèle peut posséder les types et leurs validations. Le point d’entrée choisit les opérations à appeler et gère les entrées ou sorties disponibles. Évite un fichier par procédure : trop de petits modules rendent les chemins plus difficiles à suivre sans apporter une frontière utile.

Le sens des dépendances doit rester lisible. Un module de bas niveau ne devrait pas dépendre du point d’entrée ; le point d’entrée peut appeler les modules spécialisés. Lorsqu’un import forme un cycle ou que deux modules dépendent mutuellement de détails internes, cherche une interface plus stable ou un module commun qui porte les types partagés.

Stabiliser une interface publique

Une signature exportée devient une dépendance pour ses appelants. Renommer le module, changer les paramètres ou transformer un type public peut demander des corrections dans plusieurs fichiers. Avant une modification, recherche tous les imports concernés, puis actualise le producteur et les appelants ensemble.

Expose une constante seulement si sa valeur fait partie du contrat. Si les appels doivent utiliser un comportement et non la valeur interne d’un réglage, exporte plutôt une procédure qui applique ce réglage. Cette séparation permet de changer le détail sans réécrire chaque appelant.

Correction du parcours entre deux fichiers

Le module calcul exporte additionner ; main importe le chemin sous le nom local calcul ; l’appel est calcul::additionner(20, 22). Il faut aussi fournir la racine de recherche examples. Le code de sortie confirmé est 0.

Atelier guidé : deux fichiers, un contrat

  1. Crée calcul.vit et déclare le module exercice::calcul. Exporte deux procédures : addition et multiplication.
  2. Crée main.vit dans un module distinct et importe exercice::calcul.
  3. Appelle les deux procédures via leur chemin qualifié et vérifie les résultats attendus avec des assertions ou un point de retour simple.
  4. Rends une troisième procédure privée. Tente de l’appeler depuis main, lis le diagnostic, puis décide si elle doit réellement faire partie de l’interface.
Corrigé détaillé de l’atelier

Le fichier producteur porte space exercice::calcul; et exporte les procédures. Le fichier principal déclare son propre chemin, importe exercice::calcul sous un alias et appelle les fonctions avec cet alias suivi de ::. La racine de recherche doit contenir le répertoire exercice.

Une procédure sans export doit rester inaccessible depuis le module appelant. Si l’appel échoue sur cette procédure, le diagnostic correspond à la frontière de visibilité ; rendre toutes les déclarations publiques n’est pas une correction automatique. N’exporte le helper que si un autre module a réellement besoin de l’appeler.

Le cas de référence du dépôt utilise VITTE_MODULE_PATH=examples, importe le module calcul et s’exécute avec le frontend natif. La preuve s’applique à ce chemin et à ces signatures ; les imports groupés ou réexports peuvent suivre un autre niveau de support.
