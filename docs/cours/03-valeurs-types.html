Une variable est une liaison nommée

On déclare une variable locale avec let. Ici, le type est écrit après les deux-points :

proc calculer() -> i64 {
    let prix: i64 = 12;
    let quantite: i64 = 3;
    let total: i64 = prix * quantite;
    return total;
}

Le nom total désigne la valeur calculée par prix * quantite. L’annotation : i64 précise qu’il s’agit d’un entier signé sur 64 bits. L’écrire explicitement est utile pendant l’apprentissage : tu vois quels types circulent et tu obtiens des diagnostics plus faciles à comprendre.

Vitte sait aussi inférer certains types à partir de la valeur initiale dans les contextes pris en charge. En cours, garde les annotations dans les premiers exemples. Elles rendent l’intention visible et évitent de confondre « le compilateur peut le deviner » avec « la valeur n’a pas de type ».

Immuable par défaut, mutable sur demande

Une déclaration simple avec let ne peut pas être remplacée ensuite. Pour une valeur qu’on doit faire évoluer, écris let mut et utilise set pour l’affectation :

proc compteur() -> i64 {
    let mut nombre: i64 = 0;
    set nombre = nombre + 1;
    set nombre = nombre + 1;
    return nombre;
}

La différence est intentionnelle. Si une variable ne change pas, le lecteur peut suivre une seule valeur pendant toute la durée de son bloc. La mutabilité est une décision locale qu’on peut repérer dans le code. Si le compilateur signale qu’une variable est immuable, demande-toi d’abord si elle a vraiment besoin de changer ; ajoute mut uniquement si oui.

Exemple vérifié : type, liaison mutable et affectation

build/bin/vitte run examples/tutorials/valeurs.vit --quiet --no-color

Résultat confirmé : code de sortie 0.

Les types courants

Les programmes du dépôt utilisent des entiers signés comme i8, i32 et i64, des entiers non signés comme u8 et u64, des flottants comme f32 et f64, ainsi que bool, char et string. Le type int est aussi utilisé pour le code de sortie du programme d’exemple.

Le choix du type décrit une contrainte réelle. Un âge ou une quantité ne sont pas des nombres arbitraires : leur plage et leur signe comptent. Une conversion explicite comme valeur as u64 indique au lecteur qu’on change de représentation. Elle ne garantit pas à elle seule que la valeur convient à la nouvelle plage ; pour une conversion sensible, préfère une fonction de conversion vérifiée de la bibliothèque quand elle est utilisable.

proc main() -> i64 {
    let mut octets: [2]u8 = [7 as u8, 255 as u8];
    set octets[0] = 9 as u8;

    if octets[0] == 9 and octets[1] == 255 {
        return 0;
    }
    return 1;
}

Constantes, littéraux et tableaux

Une constante nommée au niveau du module utilise const. Elle convient à une valeur stable qu’on veut nommer et réutiliser. static est une autre déclaration de valeur globale dans la grammaire ; ne la choisis pas par habitude : vérifie le comportement attendu par le compilateur et la convention de ton projet.

const TAILLE: i64 = 3;
const COULEURS: [3]i64 = [12, 24, 36];

proc premier() -> i64 {
    return COULEURS[0];
}

[3]i64 signifie un tableau de trois éléments de type i64. La longueur fait partie du type. Les tableaux sont pratiques quand le nombre d’éléments est connu ; les tranches et collections de la bibliothèque ont d’autres contrats et sont abordées plus loin.

Une habitude utile : suivre le type de chaque étape

Quand tu lis une expression, demande-toi : quel type a chaque opérande ? Quel type produit l’opération ? Est-ce que la procédure appelée attend le même type ? Par exemple, ajouter un u8 à un i64 peut nécessiter une conversion explicite. Cette discipline te protège des erreurs de largeur et des mélanges signe/non-signé.

À retenir

Un type n’est pas une décoration. Il définit une plage de valeurs et les opérations disponibles. Une conversion devrait correspondre à une décision que tu peux expliquer.

Comprendre la différence entre valeur et liaison

Dans let total: i64 = prix * quantite;, total est le nom d’une liaison et prix * quantite produit une valeur. Si tu écris ensuite let avec_tax: i64 = total + taxe;, tu crées une autre liaison à partir de la valeur précédente. Rien n’a modifié total.

Pour changer la valeur associée à un nom existant, Vitte rend la décision visible dans deux endroits : la déclaration porte mut, puis l’instruction de mise à jour porte set. Cette paire évite de confondre la création d’un calcul avec la modification d’un état.

proc compter() -> i64 {
    let initial: i64 = 2;
    let double: i64 = initial * 2;
    let mut cumul: i64 = double;
    set cumul = cumul + 1;
    return cumul;
}

Le parcours est : initial = 2, double = 4, cumul = 4, puis cumul = 5. Les noms immuables gardent leur valeur ; seul cumul est réaffecté.

Choisir un type numérique avec méthode

Pour une quantité calculable, commence par identifier si elle peut être négative, si elle peut contenir une fraction et quelle précision ou plage le domaine exige. Un i64 est un entier signé ; un u64 est non signé ; f64 représente une valeur à virgule flottante. Ne choisis pas un type uniquement parce qu’il semble « assez grand » : les conversions et les opérations doivent rester cohérentes entre les paramètres, les variables et le résultat.

  • Une comparaison telle que quantite >= 0 traduit une règle métier si les valeurs négatives n’ont aucun sens.
  • Une conversion valeur as u8 demande une nouvelle représentation ; elle n’est pas à elle seule une validation de plage.
  • Une constante nommée donne un endroit unique à une limite fixe, mais il faut encore vérifier que sa valeur est correcte pour le calcul.

Le comportement du dépassement arithmétique dépend du chemin de compilation et des vérifications effectuées. Ne compte pas sur un dépassement qui « devrait sûrement » s’enrouler : établis les bornes avec le compilateur, la bibliothèque et les tests réellement ciblés.

Comment lire un diagnostic de type

Lorsqu’un type est refusé, pars de la valeur la plus proche du diagnostic. Vérifie d’abord le type déclaré à gauche, ensuite le type de l’initialiseur ou de l’expression, puis les types des opérandes. Une conversion ne doit arriver qu’après que tu as choisi la représentation voulue.

Par exemple, si une procédure attend un i64 et reçoit un u8, demande-toi si la quantité est réellement toujours dans la plage signée attendue. Une conversion forcée peut satisfaire une signature sans satisfaire la règle métier. Dans les données venant de l’extérieur, préfère une conversion contrôlée et un cas d’erreur explicite lorsqu’ils sont disponibles.

Atelier guidé : calculer une facture

  1. Déclare prix_unitaire et quantite comme des i64, puis calcule un sous-total dans une troisième liaison.
  2. Déclare une taxe entière et calcule un total. Écris les parenthèses nécessaires pour rendre la règle de calcul évidente.
  3. Ajoute une variable mutable visites, augmente-la deux fois avec set, et renvoie sa valeur.
  4. Provoque un diagnostic en affectant une liaison immuable. Lance une vérification sémantique disponible (le dépôt documente notamment compile --stop-after-sema), lis le message, puis décide si la bonne correction est d’ajouter mut ou de supprimer la modification inutile.
Corrigé détaillé de l’atelier

Avec un prix unitaire de 12 et une quantité de 3, le sous-total vaut 12 * 3 = 36. Si la taxe choisie pour l’exercice est une valeur fixe de 6, le total est 36 + 6 = 42. Si tu calcules plutôt un pourcentage, précise l’unité, l’ordre des opérations et la règle d’arrondi avant d’écrire la formule.

La variable visites doit commencer avec let mut visites: i64 = 0;. Deux instructions set visites = visites + 1; laissent la valeur à 2. Une variable déclarée seulement avec let ne peut pas être réaffectée ; la correction consiste soit à ajouter mut si le changement est nécessaire, soit à calculer une nouvelle liaison si tu veux conserver l’ancienne valeur.

Une conversion comme 255 as u8 ne démontre pas à elle seule que toute valeur est dans la plage voulue. Les types et les conversions doivent exprimer une décision sur les données, pas servir à faire taire un diagnostic.
