Nommer un module

space outils::calcul;

La grammaire permet des segments séparés par :: ou /. Le manifeste JSON documente :: comme syntaxe de chemin de module. Garde les noms de fichier, le chemin logique space, les imports et le manifeste du paquet cohérents.

Importer

use core::types::option::{Option, option_some};
use outils::calcul as calcul;
use outils::math::*;

use prend un chemin, un alias, un groupe de noms ou un glob. Les alias donnent un nom local ; les imports globaux font entrer plusieurs symboles dans la portée et peuvent rendre leur provenance ambiguë. Préfère les imports explicites dans une API que d’autres personnes doivent relire.

Exporter

export const REPONSE: i64 = 42;
export proc calculer() -> i64 { return REPONSE; }
export { REPONSE, calculer };

La grammaire fournit des formes d’export de déclaration et des listes d’exports. Le compilateur a des limites sur certains réexports ; un nom accessible localement n’est pas nécessairement réexportable depuis un autre module.

Résolution et visibilité

Un nom qualifié comme json::parser::parser donne la provenance d’une déclaration. L’importeur recherche les modules dans des racines configurées. Le CLI documente notamment VITTE_MODULE_PATH pour ajouter des racines et --manifest-path/--project-root pour préciser le projet.

La documentation de core indique que les imports doivent actuellement venir du chemin complet : core::prelude ne fournit pas une façade complète par réexport. Pour diagnostiquer un import, vérifie successivement le chemin logique, la racine de résolution, l’existence du fichier et l’export du symbole utilisé.

Organisation de paquet

Le paquet JSON fournit un exemple de manifeste package.toml avec nom, version, fichier d’entrée, racine du module et syntaxe de chemin. Consulte la documentation de la release v0.1.1 pour l’installation et l’utilisation de VITTE_MODULE_PATH.
