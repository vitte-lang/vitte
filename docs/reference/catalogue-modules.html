JSON : le premier paquet externe

Le module JSON est la bibliothèque de données la plus complète présentée ici. Sa release autonome {{ json_package.release_tag | escape }} est liée à un tag immuable et fournit une archive avec son SHA-256. Le registre lit le nom, la version, l’URL, l’empreinte, la licence et les versions compatibles dans modules/json/registry.toml ; la branche main reste une source de développement et n’est pas une référence d’installation reproductible.

Installer le paquet JSON

Depuis la racine de votre projet, exécutez la commande proposée :

vitte install json

Pour épingler JSON {{ json_package.version | escape }} :

vitte install json --version {{ json_package.version | escape }}

Vitte doit être compatible avec {{ json_package.compatible_vitte_versions | join: ', ' }}. Il faut aussi une connexion Internet et les commandes curl et tar dans le PATH. Le résultat attendu est Installed json {{ json_package.version | escape }} in this project. Les sources vont dans .vitte/modules/json; vitte.packages.toml et vitte.lock enregistrent la dépendance résolue. Pour l’utilisateur courant, ajoutez --global.

Les fichiers parser/array.vit, parser/object.vit, parser/value.vit et encode/escape.vit sont des brouillons internes non installés par le Makefile maintenu. Utilisez les API exportées de parser/parser, encode/encoder et des modules déclarés dans leur documentation.

Lire les preuves de support

  • Vérification du paquet : make -C modules/json check contrôle la disposition attendue et les sources maintenues avec le compilateur indiqué par le Makefile.
  • Consommateur installé : make -C modules/json test-vitte prouve un import et une exécution du parser et de l’encodeur installés.
  • Suite complète du paquet : make -C modules/json verify inclut l’import installé et le test de concaténation dynamique fourni par le module.
  • Couverture par API : l’existence d’un export ne prouve pas que tous les types ou cas limites ont un consommateur public compilé. Lisez la documentation détaillée et les tests associés.

Les résultats des commandes dépendent du compilateur utilisé, du répertoire de travail, du chemin de modules et de la version réellement installée. Quand une commande échoue, comparez d’abord vitte --version, la version de package.toml et le dépôt d’où proviennent les sources.

Ajouter un module au catalogue

Pour que ce catalogue reste fiable, une nouvelle entrée devrait fournir au minimum :

  1. un dépôt maintenu et un lien vers ses releases ou tags ;
  2. le nom du paquet, la version, le module d’entrée et les dépendances ;
  3. la procédure exacte d’installation et la racine de résolution ;
  4. la liste des symboles réellement exportés, avec une distinction entre source et API installée ;
  5. une commande de vérification, un consommateur minimal et sa sortie attendue ;
  6. les limites connues, la cible/plateforme et la version du compilateur utilisée pour la preuve.

Pour l’état général des formes du langage, consultez la matrice de compatibilité. Pour les nouveautés entre versions, consultez Nouveautés et migrations.
