Un module présent dans le dépôt n’est pas forcément une release autonome.

Ce catalogue indique le dépôt d’origine, le numéro de release consulté et la copie locale lorsqu’ils diffèrent. L’état a été relevé le 28 octobre 2026 ; les versions et fichiers publiés peuvent évoluer. Vérifiez les pages Releases avant de choisir un paquet pour un projet.

Cette première édition ne transforme pas les répertoires de sources en promesses de compatibilité. Un module ne sera ajouté comme paquet utilisable que lorsque son nom d’import, sa version, son mode d’installation et au moins un consommateur reproductible seront documentés.

JSON : le premier paquet externe

Le module JSON est la bibliothèque de données la plus complète présentée ici. Le dépôt public est Vitte-Foundation/json. Sa page Releases indique Json_Module_Version_0.1.0. La copie intégrée dans ce dépôt porte quant à elle 0.1.1 dans modules/json/package.toml. Ces numéros décrivent deux sources de distribution : ne remplacez pas l’un par l’autre sans avoir synchronisé les dépôts.

Ouvrir la page officielle du module JSON → Consulter la référence technique

Installer depuis le dépôt Vitte

Pour utiliser la copie intégrée au dépôt du compilateur, les commandes suivantes s’exécutent depuis la racine de Vitte :

make -C modules/json verify
make install PREFIX="$HOME/.local"
export PATH="$HOME/.local/bin:$PATH"

Le module est alors installé sous $HOME/.local/share/vitte/modules/json. Si le compilateur ne découvre pas automatiquement cette racine, ajoutez son parent à VITTE_MODULE_PATH :

export VITTE_MODULE_PATH="$HOME/.local/share/vitte/modules"
build/bin/vitte compile application.vit -o application

Sous Windows, le séparateur de chemins de modules est le point-virgule. Le dépôt fournit également une cible de vérification qui installe le paquet dans un répertoire temporaire, compile un consommateur qui importe le parser et l’encodeur, puis exécute ce consommateur. Pour un clone autonome du dépôt JSON, suivez les instructions et les fichiers de la release correspondante ; les chemins modules/json ci-dessus sont ceux du dépôt monorepo Vitte.

Les fichiers parser/array.vit, parser/object.vit, parser/value.vit et encode/escape.vit sont des brouillons internes non installés par le Makefile maintenu. Utilisez les API exportées de parser/parser, encode/encoder et des modules déclarés dans leur documentation.

Lire les preuves de support

  • Vérification du paquet : make -C modules/json check contrôle la disposition attendue et les sources maintenues avec le compilateur indiqué par le Makefile.
  • Consommateur installé : make -C modules/json test-vitte prouve un import et une exécution du parser et de l’encodeur installés.
  • Suite complète du paquet : make -C modules/json verify inclut l’import installé et le test de concaténation dynamique fourni par le module.
  • Couverture par API : l’existence d’un export ne prouve pas que tous les types ou cas limites ont un consommateur public compilé. Lisez la documentation détaillée et les tests associés.

Les résultats des commandes dépendent du compilateur utilisé, du répertoire de travail, du chemin de modules et de la version réellement installée. Quand une commande échoue, comparez d’abord vitte --version, la version de package.toml et le dépôt d’où proviennent les sources.

Ajouter un module au catalogue

Pour que ce catalogue reste fiable, une nouvelle entrée devrait fournir au minimum :

  1. un dépôt maintenu et un lien vers ses releases ou tags ;
  2. le nom du paquet, la version, le module d’entrée et les dépendances ;
  3. la procédure exacte d’installation et la racine de résolution ;
  4. la liste des symboles réellement exportés, avec une distinction entre source et API installée ;
  5. une commande de vérification, un consommateur minimal et sa sortie attendue ;
  6. les limites connues, la cible/plateforme et la version du compilateur utilisée pour la preuve.

Pour l’état général des formes du langage, consultez la matrice de compatibilité. Pour les nouveautés entre versions, consultez Nouveautés et migrations.
