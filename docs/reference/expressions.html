Le tableau va du niveau le moins prioritaire au plus prioritaire. Les opérateurs d’un même niveau se regroupent de gauche à droite, sauf l’affectation et ??, définis récursivement vers la droite.

Associativité et parenthèses

Les expressions arithmétiques et logiques forment des chaînes de gauche à droite. L’affectation s’associe vers la droite. Les parenthèses forcent le regroupement voulu et restent utiles même quand la priorité du langage suffirait :

let a: i64 = 2 + 3 * 4;      // multiplication d'abord
let b: i64 = (2 + 3) * 4;    // addition d'abord

La grammaire n’énonce pas à elle seule tous les effets d’évaluation ni toutes les règles de typage. Pour des opérandes qui modifient l’état, découpe l’expression en plusieurs instructions afin d’éviter une dépendance implicite à l’ordre d’évaluation.

Familles d’expressions

  • Expressions primaires : littéraux, chemins, self, listes de valeurs entre crochets, parenthèses et blocs.
  • Postfixes : appels, accès indexé, champs et suffixe ?.
  • Unaires : signes, négation logique/bit à bit, déréférence, emprunt, move, ref, await.
  • Binaires : arithmétique, plages, décalages, bits, comparaisons et logique.
  • Affectations : expression simple et formes composées définies dans la grammaire.

Écarts syntaxe / compilation à connaître

as Type apparaît dans les sources et les tests compilés, mais pas dans la production expression du fichier EBNF canonique. Les gardes de motifs et les formes avancées de match ont le même écart : le frontend natif les accepte dans ses tests, alors que cette production EBNF ne décrit qu’un bras simple expression => ....
