Ce guide suit le dépôt Vitte {{ site.vitte_version }}.

Les noms de commandes et les étapes de compilation sont ceux du dépôt. La prise en charge du langage reste limitée à des sous-ensembles précis : consultez la matrice de compatibilité avant de conclure qu’une construction peut être compilée.

Prérequis

Pour construire le compilateur depuis les sources, prévoyez un compilateur C compatible C17, make et Git. Python 3 est également utilisé par les vérifications et scripts de développement du dépôt. Le workflow CI du projet installe ces outils avant de construire et de contrôler le compilateur.

cc --version
make --version
python3 --version
git --version

Sur macOS, les outils C et make sont fournis par les Command Line Tools de Xcode. Sur Linux, installez la chaîne de compilation C17 et make depuis le gestionnaire de paquets de votre distribution. Les commandes d’installation des paquets dépendent de l’OS et ne sont pas nécessaires si ces outils sont déjà présents.

Construire le dépôt

make est le parcours principal utilisé par le dépôt et sa CI. Depuis le répertoire dans lequel vous voulez garder les sources :

git clone https://github.com/vitte-lang/vitte.git
cd vitte
make -j2
./build/bin/vitte --version
./build/bin/vitte check examples/hello.vit

Le binaire construit par Make se trouve dans build/bin/vitte (ou build/bin/vitte.exe dans les environnements Windows du dépôt). La dernière commande vérifie un exemple du dépôt. Elle ne démontre pas que toutes les formes du langage sont prises en charge ; chaque commande passe par le frontend choisi par le compilateur.

Pour utiliser immédiatement ce binaire sans l’installer, donnez son chemin explicite :

./build/bin/vitte lex examples/hello.vit
./build/bin/vitte parse examples/hello.vit
./build/bin/vitte check examples/hello.vit
./build/bin/vitte run examples/hello.vit

Installer sous un préfixe local

Le Makefile installe le compilateur sous PREFIX/bin et le paquet JSON sous PREFIX/share/vitte/modules/json. Un préfixe dans votre dossier personnel évite de modifier l’installation système :

make install PREFIX="$HOME/.local"
export PATH="$HOME/.local/bin:$PATH"
vitte --version

Pour installer dans le préfixe système par défaut (/usr/local), il faut que votre compte ait les droits d’écriture nécessaires. Si la commande échoue avec un refus d’accès, choisissez un préfixe local ou utilisez la procédure d’administration habituelle de votre système.

La désinstallation reprend le même préfixe :

make uninstall PREFIX="$HOME/.local"

Le Makefile accepte également DESTDIR pour préparer une installation dans un répertoire de staging, par exemple lors de la fabrication d’un paquet. Ce répertoire sert au packaging ; il ne remplace pas le préfixe utilisé à l’exécution.

Résoudre les modules, dont JSON

Pour une copie de travail du dépôt, VITTE_MODULE_PATH doit contenir la racine qui abrite les espaces de noms. Pour utiliser json::parser::parser, indiquez donc le dossier modules, et non le seul dossier modules/json :

VITTE_MODULE_PATH="$PWD/modules" \
  ./build/bin/vitte run modules/json/tests/import_smoke.vit

Le séparateur entre plusieurs racines suit le système hôte : : sur les systèmes de type Unix et ; sous Windows. Les déclarations space, les imports use, les exports et le chemin des fichiers doivent aussi correspondre. La variable ajoute des racines de recherche ; elle ne corrige pas un chemin de module erroné.

Après make install PREFIX="$HOME/.local", le module JSON est placé dans $HOME/.local/share/vitte/modules/json. Si votre configuration ne découvre pas cette racine automatiquement, ajoutez $HOME/.local/share/vitte/modules à VITTE_MODULE_PATH. Pour installer ou vérifier uniquement le paquet JSON, son Makefile fournit des cibles dédiées :

make -C modules/json check
make -C modules/json verify

verify lance la vérification des sources et le test d’import installé décrit dans modules/json/Makefile. La fiche Module JSON détaille ses espaces, fonctions, limites et diagnostics.

Isoler la première étape en échec

Le pipeline sépare la lecture des caractères, la syntaxe, l’analyse sémantique et les étapes de compilation. Lancez la commande la plus proche de l’étape que vous suspectez, puis avancez jusqu’à reproduire l’erreur :

./build/bin/vitte lex chemin/vers/main.vit
./build/bin/vitte parse chemin/vers/main.vit
./build/bin/vitte check chemin/vers/main.vit
./build/bin/vitte compile chemin/vers/main.vit --stop-after-sema
./build/bin/vitte compile chemin/vers/main.vit
./build/bin/vitte run chemin/vers/main.vit
  • lex aide à repérer un caractère ou un littéral mal formé.
  • parse vérifie la structure syntaxique reconnue par le parseur.
  • check vérifie le programme jusqu’au niveau exposé par le frontend sélectionné.
  • compile --stop-after-sema s’arrête après l’analyse sémantique lorsque cette option est disponible pour la commande.
  • compile et run demandent les étapes de backend, de liaison ou d’exécution et peuvent échouer si une construction n’est pas encore prise en charge.

Un succès de parse signifie seulement que la syntaxe a été acceptée. Il ne prouve ni que les noms et les types sont valides, ni que la forme atteint le backend. Reportez-vous à la matrice par construction et à la référence CLI.

Erreurs fréquentes

SymptômeVérificationSuite à donner
vitte: command not foundLe binaire n’est pas dans PATH, ou l’installation n’a pas abouti.Lancez ./build/bin/vitte --version depuis le dépôt, puis vérifiez que $HOME/.local/bin est dans PATH si vous avez installé sous ~/.local.
make ne trouve pas le compilateur CLe compilateur manque, ou CC pointe vers un exécutable absent.Installez une chaîne C17 et vérifiez cc --version. Si vous choisissez un autre compilateur installé, passez son nom à Make, par exemple make CC=clang.
Le fichier source est introuvableLe chemin est relatif au répertoire courant.Vérifiez pwd et le nom du fichier ; donnez un chemin absolu si la commande est lancée depuis un autre répertoire.
Le module ou le symbole importé est introuvableLa racine de recherche, le chemin space, l’import et l’export ne concordent pas.Vérifiez que VITTE_MODULE_PATH pointe vers le parent du dossier du module, puis contrôlez l’orthographe du chemin et la visibilité du symbole.
La syntaxe passe mais check ou l’analyse sémantique échoueLa grammaire et l’analyseur ne valident pas les mêmes propriétés que l’analyse des noms et des types.Suivez le diagnostic et réduisez le fichier à la déclaration ou l’expression concernée. Consultez la fiche de référence correspondante.
Le backend refuse une forme pourtant analyséeLa construction est peut-être décrite par l’EBNF et reconnue par l’analyseur, sans génération supportée.Recherchez-la dans la matrice de compatibilité. Un diagnostic backend est une limite d’implémentation, pas une erreur de configuration du système.
La compilation C ou la liaison échoueLe programme a dépassé les premières étapes ; le compilateur C hôte ou l’édition de liens peut être en cause.Conservez le diagnostic complet, la version du compilateur, la commande et le code C généré lorsque celui-ci est produit. Vérifiez la disponibilité du compilateur C utilisé par le pilote.

Préparer un signalement utile

Si le problème subsiste, fournissez les éléments qui permettent de reproduire la même étape :

  1. la version affichée par vitte --version ;
  2. le système, le compilateur C et les options de construction ;
  3. la commande exacte et le répertoire depuis lequel elle est lancée ;
  4. le diagnostic complet, y compris son code et l’étape du pipeline ;
  5. un petit fichier source qui reproduit le problème sans données secrètes.

Recherchez d’abord une issue existante, puis ouvrez un signalement sur GitHub si le problème est nouveau. Pour une question de compatibilité, indiquez aussi si l’échec se produit à la grammaire, à l’analyseur, à l’analyse sémantique, au backend ou pendant l’exécution.
