Compiler Architecture (Current Implementation)

This page describes the compiler paths that exist in this repository today.

Default executable

The default Makefile and CMake targets are configured to link the native Vitte pipeline from src/compiler/ into the CLI. The pipeline handles compile, run, check, --emit-c, and --emit-ir through native frontend analysis and HIR/IR validation. The native IR C17 backend emits supported programs by default; constructs without IR lowering use the native AST emitter as a compatibility path. Bootstrap C still provides CLI/source-graph setup, inspection, and the host C compiler/linker boundary. This is staged integration, not a full self-hosted compiler. The current make native-frontend source build stops on diagnostics in arena, scanner, HIR, IR, and semantic modules, so a fresh executable has not yet been built from these sources.

The active path begins at src/bootstrap/main.c and runs through the CLI driver in src/bootstrap/cli/:

source/module graph → bootstrap CLI → Vitte lexer/parser/sema
                    → validated HIR → sealed IR → Vitte IR-to-C17
                    → host C compiler/linker
                    \→ Vitte AST-to-C17 for IR-incomplete constructs
Command or stageCurrent behavior
checkStops after frontend semantic analysis on the native subset or compatibility path.
compileUses native HIR/IR and the IR C17 backend for supported programs; uses native AST emission for IR-incomplete constructs. Sources with unsupported features use the bootstrap compatibility pipeline. Native diagnostics remain authoritative once that frontend is selected.
runUses the selected frontend path and then executes the generated program through the host toolchain.
--emit-irPrints validated IR from the selected pipeline.

Implementation map

  • src/bootstrap/main.c — process entry point.
  • src/bootstrap/cli/command_spec.def — declared CLI commands and options.
  • src/bootstrap/cli/execution.c and pipeline.c — command routing and phase setup.
  • src/compiler/driver/pipeline.vitte — native phase and backend dispatch.
  • src/compiler/ir/ir.vitte — HIR-to-IR lowering and validation.
  • src/compiler/backend/c17/ir_emitter.vitte — default C17 backend for supported IR.
  • src/compiler/backend/c17/ast_emitter.vitte — AST compatibility emitter.

Staged native Vitte compiler

Native Vitte pipeline

The active Vitte frontend includes source management at src/compiler/source/source.vitte, lexing at src/compiler/lexer/lexer.vitte, partial parsing at src/compiler/parser/parser.vitte, semantic analysis at src/compiler/sema/sema.vitte, and HIR/IR lowering and validation at src/compiler/hir/hir.vitte and src/compiler/ir/ir.vitte. Supported programs reach src/compiler/backend/c17/ir_emitter.vitte; the AST emitter handles constructs whose IR lowering is incomplete.

Grammar and feature status

grammar/vitte.ebnf is the canonical grammar. Grammar acceptance does not guarantee semantic or backend support. The single feature-status matrix records the current limits across the grammar, bootstrap stages, default backend, alternate route and native port: Vitte language and toolchain coverage.

The documentation audiences and language policy are defined in Documentation Policy. For file-level details, see the compiler source map and native frontend port notes.
