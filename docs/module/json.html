Ce que fournit le paquet

Le module prend une chaîne Vitte contenant du JSON, la transforme en tokens, construit une valeur Vitte, permet d’inspecter et de valider cette valeur, puis peut la réencoder. Le paquet est écrit en Vitte et le manifeste ne déclare aucune dépendance native. Le parsing travaille sur une chaîne déjà fournie par l’application : l’ouverture d’un fichier ou la lecture de stdin relève de la couche d’entrée du programme, pas du parser JSON.

texte JSON → lexer → tokens → parser → JsonValue → encodeur → texte JSON

Cette séparation permet de tester les étapes individuellement : examiner le lexer, parser un flux de tokens déjà disponible, appliquer un schéma métier après parsing ou produire une sortie compacte et indentée.

Démarrage rapide

use json::parser::parser::{JsonParseResult, parse};
use json::encode::encoder::{encode_compact};

proc reformater(source: string) -> int {
    let parsed: JsonParseResult = parse(source);
    if not parsed.ok {
        print(parsed.report.message);
        return 1;
    }

    let encoded = encode_compact(&parsed.value);
    if not encoded.ok {
        print("L’encodage JSON a échoué.");
        return 2;
    }

    print(encoded.text);
    return 0;
}

Ce parcours utilise parse et encode_compact, API du consommateur installé qui a été compilé puis exécuté avec Vitte {{ json_package.compatible_vitte_versions | join: ', ' }}. Contrôlez ok avant d’accéder à la valeur parsée ou au texte encodé. parse_strict est également disponible pour refuser les clés d’objet dupliquées.

Limites et données non fiables

Dans la copie intégrée 0.1.1, les profils par défaut bornent le nombre de tokens à 1 048 576, la source à 268 435 456 unités, la longueur d’une chaîne décodée à 16 777 216 et celle d’un nombre à 4 096. Le parser limite la profondeur à 512, le nombre global de valeurs à 1 048 576, les éléments par tableau et les membres par objet à 1 048 576, et les clés décodées à 16 777 216.

Ces maxima ne remplacent pas les budgets adaptés à votre service. Pour une requête réseau de petite taille, créez des limites plus basses et appelez parse_strict_with_limits. La limite de source intervient après que l’application a déjà construit la chaîne ; limitez donc également la lecture du fichier ou du corps HTTP.

  • Choisissez le mode strict si des clés dupliquées doivent être refusées sans ambiguïté.
  • Vérifiez ok, le type racine, les champs requis et les plages métier.
  • Ne supposez pas que la présence d’un champ garantit le type attendu.
  • Ne réencodez pas une valeur qui a échoué au parsing ou à la validation applicative.
  • Gardez en tête qu’un document valide selon JSON peut rester invalide pour le schéma de votre application.

Parcours complet vérifié dans un projet vide

Le parcours ci-dessous a été exécuté depuis un dossier temporaire sans manifeste ni module préinstallé, avec Vitte {{ json_package.compatible_vitte_versions | join: ', ' }} et le registre public. Après vitte install json, le manifeste indique dependency.json = "{{ json_package.version | escape }}". Le verrou TOML contient ces champs :

package.json.version = "{{ json_package.version | escape }}"
package.json.source = "{{ json_package.download_url | escape }}"
package.json.checksum = "sha256:{{ json_package.sha256 | escape }}"

Créez main.vit dans ce dossier :

space app;

use json::encode::encoder::{
    encode_compact
};
use json::parser::parser::{
    JsonParseResult,
    parse
};

export proc main() -> int {
    let parsed: JsonParseResult =
        parse("{\"ready\":true}");

    if not parsed.ok {
        return 1;
    }

    let encoded =
        encode_compact(&parsed.value);

    if not encoded.ok {
        return 2;
    }

    print(encoded.text);

    if encoded.text.length != 14 ||
       encoded.text[0] != '{' ||
       encoded.text[1] != '"' ||
       encoded.text[2] != 'r' ||
       encoded.text[7] != '"' ||
       encoded.text[8] != ':' ||
       encoded.text[9] != 't' ||
       encoded.text[13] != '}' {
        return 3;
    }

    return 0;
}

Compilez puis lancez le consommateur :

vitte compile main.vit -o consumer
./consumer

Résultat observé : la compilation réussit, le programme termine avec le code 0 et affiche :

{"ready":true}

Les contrôles du programme comparent aussi la longueur et plusieurs caractères de la sortie encodée. Sur Windows, exécutez le binaire produit avec le nom et l’extension générés pour votre cible.

Refus d’une version de Vitte incompatible

Le registre ne propose actuellement JSON {{ json_package.version | escape }} qu’aux versions compatibles listées plus haut. Le contrôle a aussi été exécuté avec un compilateur de test isolé marqué Vitte 0.1.2 : vitte install json retourne le code 1 et affiche :

vitte install: no stable compatible release found for 'json'

Le refus intervient avant l’installation : aucun manifeste ni fichier de verrouillage n’est créé. Une future version de JSON pourra être installée dès que le registre l’enregistrera comme compatible avec la version de Vitte concernée.
