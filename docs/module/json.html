Ce que fournit le paquet

Le module prend une chaîne Vitte contenant du JSON, la transforme en tokens, construit une valeur Vitte, permet d’inspecter et de valider cette valeur, puis peut la réencoder. Le paquet est écrit en Vitte et le manifeste ne déclare aucune dépendance native. Le parsing travaille sur une chaîne déjà fournie par l’application : l’ouverture d’un fichier ou la lecture de stdin relève de la couche d’entrée du programme, pas du parser JSON.

texte JSON → lexer → tokens → parser → JsonValue → encodeur → texte JSON

Cette séparation permet de tester les étapes individuellement : examiner le lexer, parser un flux de tokens déjà disponible, appliquer un schéma métier après parsing ou produire une sortie compacte et indentée.

Démarrage rapide

use json::parser::parser::{JsonParseResult, parse_strict};
use json::encode::encoder::{JsonEncodeResult, encode_pretty};

proc reformater(source: string) -> int {
    let parsed: JsonParseResult = parse_strict(source);
    if not parsed.ok {
        print(parsed.report.message);
        return 1;
    }

    let encoded: JsonEncodeResult = encode_pretty(&parsed.value);
    if not encoded.ok {
        print("L’encodage JSON a échoué.");
        return 2;
    }

    print(encoded.text);
    return 0;
}

parse_strict rejette un document mal formé et les clés d’objet répétées. Le résultat doit être vérifié avant d’accéder à value. De même, l’encodeur renvoie une forme de résultat : n’utilisez text qu’après avoir contrôlé ok.

Limites et données non fiables

Dans la copie intégrée 0.1.1, les profils par défaut bornent le nombre de tokens à 1 048 576, la source à 268 435 456 unités, la longueur d’une chaîne décodée à 16 777 216 et celle d’un nombre à 4 096. Le parser limite la profondeur à 512, le nombre global de valeurs à 1 048 576, les éléments par tableau et les membres par objet à 1 048 576, et les clés décodées à 16 777 216.

Ces maxima ne remplacent pas les budgets adaptés à votre service. Pour une requête réseau de petite taille, créez des limites plus basses et appelez parse_strict_with_limits. La limite de source intervient après que l’application a déjà construit la chaîne ; limitez donc également la lecture du fichier ou du corps HTTP.

  • Choisissez le mode strict si des clés dupliquées doivent être refusées sans ambiguïté.
  • Vérifiez ok, le type racine, les champs requis et les plages métier.
  • Ne supposez pas que la présence d’un champ garantit le type attendu.
  • Ne réencodez pas une valeur qui a échoué au parsing ou à la validation applicative.
  • Gardez en tête qu’un document valide selon JSON peut rester invalide pour le schéma de votre application.

Installation et import

Dans une copie du dépôt Vitte, les commandes suivantes vérifient et installent le paquet intégré :

make -C modules/json verify
make install PREFIX="$HOME/.local"
export PATH="$HOME/.local/bin:$PATH"
export VITTE_MODULE_PATH="$HOME/.local/share/vitte/modules"

Le répertoire donné à VITTE_MODULE_PATH est le parent de json/, pas le dossier json lui-même. Le séparateur de plusieurs chemins est : sur les systèmes Unix et ; sous Windows. Pour les artefacts du dépôt autonome et leurs sommes, partez de la page Releases JSON ; ne déduisez pas leur contenu du numéro de la copie intégrée.

Vérifications disponibles

Pour la copie JSON 0.1.1 du dépôt Vitte, les commandes ci-dessous constituent les points de départ reproductibles :

make -C modules/json check-library test-parse
make -C modules/json verify

verify contrôle la disposition du paquet, compile et exécute un consommateur qui importe le parser et l’encodeur installés, puis lance le test de concaténation dynamique. Les tests ciblés couvrent également les erreurs de parsing, les limites, Unicode et les nombres. La réussite de ces cibles ne prouve pas séparément chaque fonction exportée ni chaque taille de document réelle en production.
