Contributing to the compiler

This page helps contributors choose what to read before changing the repository. It describes active boundaries and points to topic guides instead of asking readers to browse a file inventory.

Implementation status

The default executable uses the C17 bootstrap for the active compiler path. Native Vitte modules are being integrated in stages; the maintained coverage matrix identifies complete, partial, experimental, and absent behavior.

  • Check an implementation claim: read the coverage matrix.
  • Understand the active flow: read compiler architecture.
  • Prepare a contribution: start with the contribution guide.

Short reading orders

  • Change a language rule: grammar and language reference → coverage matrix → the relevant implementation and checks.
  • Change a diagnostic or driver: diagnostics guide → compiler architecture → bootstrap contract.
  • Work on the native port: read the active bootstrap contracts and compiler architecture. Historical migration plans and file maps are grouped under secondary project resources.

Guides by topic

  • Compiler guides by topic — language, bootstrap, build, governance, and profiling.
  • Compiler diagnostics — codes, phases, and output formats.
  • Compiler build guide — tools and development commands.
  • Secondary project resources — reports, roadmaps, and migration history.

Reading rule

A command being recognized by the CLI does not guarantee every language construct works through to a generated program. Check end-to-end status in the coverage matrix before documenting or depending on a feature.
