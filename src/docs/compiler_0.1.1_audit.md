# Audit de stabilisation de Vitte 0.1.1

Audit du 25 novembre 2026. Version déclarée dans `VERSION` : `0.1.1`. Le commit observé par la CI est [`2f940dc`](https://github.com/vitte-lang/vitte/commit/2f940dc70ed9583d3300b4784166dd4a17ed3061). Les liens de jobs ci-dessous enregistrent des exécutions sur un checkout propre de ce commit. Les priorités et suivis renvoient à la [checklist de stabilisation #43](https://github.com/vitte-lang/vitte/issues/43), à la [CLI `test`/`fmt` #45](https://github.com/vitte-lang/vitte/issues/45) et aux [paquets #46](https://github.com/vitte-lang/vitte/issues/46). Aucun responsable individuel n’est affecté à ces issues ; elles servent de suivi.

## Décision de publication

**Publication 0.1.1 différée.** Le run propre `45704899756` construit les trois binaires candidats, mais échoue ensuite : `break`/`continue` et un exemple `pick` échouent sur Linux, le staging du runtime échoue sur Linux et Windows, le smoke JSON échoue sur macOS et les trois self-hosts s’arrêtent à `bootstrap-check`. Les stages 0→3 n’ont donc pas été exécutés. Plusieurs jobs de portabilité expérimentale échouent aussi. La version `0.1.1` existe dans le dépôt, mais aucun tag `v0.1.1` ni release GitHub n’était publié au moment de cet audit.

## Contrat de support visé pour 0.1.1

Le contrat est volontairement limité à trois cibles natives de publication. Il ne vaut pas annonce de disponibilité tant que la décision de publication ci-dessus est « différée ».

| Cible | Plateforme de build et paquet | Toolchain C17 | État |
| --- | --- | --- | --- |
| Linux x86_64 | Ubuntu 24.04, paquet `amd64` | GCC/`cc` de `build-essential`; versions runner non épinglées | Cible prévue; gate rouge. |
| macOS arm64 | macOS 15, Apple Silicon, paquet arm64; minimum déclaré par le paquet : macOS 11.0 | Apple Clang de Xcode / `clang`; version runner non épinglée | Cible prévue; gate rouge. |
| Windows x86_64 | Windows 2025, paquet amd64; minimum déclaré : Windows 11; environnement MSYS2 UCRT64 | MinGW-w64 GCC (`mingw-w64-ucrt-x86_64-gcc`), C17 | Cible prévue; gates self-host et package rouges. |

Les workflows installent des toolchains mobiles sans épingler leurs numéros de version. La promesse est donc la famille C17 et les runners ci-dessus, pas une version mineure reproductible du compilateur C. Cette limite doit rester explicite jusqu’à ce que les dépendances de build soient verrouillées.

Depuis la racine d’un checkout, les commandes de référence sont :

```sh
make MODE=release -j2
make MODE=release bootstrap-check
make MODE=release test-runtime
make MODE=release test-core
make MODE=release test-core-native
make MODE=release test-native-bootstrap-parity test-corpus
make MODE=release bootstrap-selfhost
```

Le build utilise le compilateur C trouvé par `make` (`cc`, puis `clang`, puis `gcc`) ou la valeur explicite de `CC`, et exige le mode C17. Le seed se construit seul avec `make bootstrap`; le binaire principal est `build/bin/vitte` (Windows : `build/bin/vitte.exe`) et le seed `build/bin/vitte-bootstrap` (Windows : `build/bin/vitte-bootstrap.exe`). Les tests d’installation s’exécutent avec `scripts/ci/real-install-smoke.sh` et `scripts/ci/package-install-smoke.sh` (Windows : variantes `.ps1`).

### Sous-ensemble du langage

La liste normative des cas vérifiés est la matrice [État du support](../../docs/reference/support.html), lue avec la grammaire canonique [`grammar/vitte.ebnf`](../../grammar/vitte.ebnf). Pour 0.1.1, une construction n’est promise que dans les lignes marquées **Disponible**, pour le frontend et les phases explicitement indiqués par la ligne et les tests liés. Une production EBNF ou un parse réussi seuls ne suffisent pas. Les lignes **Expérimental**, **Non implémenté** ou **Non prouvé** ne font pas partie du contrat.

Limites intentionnelles : `assert(condition);` exige les parenthèses; les variantes s’écrivent `State.Ready` comme valeur construite et `State::Ready` dans un motif `match`; async/await est différé et mono-thread au premier `await`, sans ordonnanceur général ni `spawn`/`yield`; `unsafe` ne prouve pas la sûreté mémoire; les durées de vie et l’exclusivité des références ne sont pas vérifiées complètement; les macros et déplacements partiels restent limités; `vitte test` et `vitte fmt` sont indisponibles; le paquet JSON 0.1.1, qui utilise une syntaxe `assert` hors de la grammaire, est reporté.

## Séparation des correctifs et reports

Les corrections C-01, C-03, C-06, C-07, C-08 et C-11 réparent un comportement déjà annoncé, les tests ou la documentation. C-02 reste un crash natif confirmé; C-05 reste un échec de staging à valider après le changement du parser. Le support de la syntaxe sans parenthèses des assertions et l’implémentation de `test`/`fmt` étendent le langage ou les commandes disponibles : ils restent séparés et reportés dans #46 et #45. Le run CI suivant doit confirmer ces correctifs puis atteindre les stages 0→3; un échec à une transition doit recevoir une fixture ciblée avant de poursuivre.
