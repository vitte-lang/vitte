# src/unicode

Category: Unicode.

Purpose: strict UTF-8 validation and Unicode XID identifier classification.

The identifier ranges are generated by
`scripts/generate-unicode-xid.py` from Python's `unicodedata` XID properties,
which implement the Unicode Standard Annex #31 identifier rules. The language
contract is frozen to Unicode 16.0.0. The generator rejects both a Python
runtime backed by another Unicode database and a requested version other than
16.0.0, so a host upgrade cannot silently change the language.

Generation always writes UTF-8 with LF line endings. `unicode-check` compares
the generated bytes, including line endings, and therefore catches accidental
platform conversions. Run `make -C src unicode-table` only when deliberately
updating the language contract, then run `make -C src unicode-check` and
`make -C src test-unicode-generation` in CI. The latter regenerates twice,
checks the pinned version, rejects CRLF artifacts and verifies the generated
metadata.

The frontend token tests cover valid XID identifiers, invalid starts,
canonically composed and decomposed spellings, invalid scalars and malformed
UTF-8. Vitte deliberately hashes source bytes and performs no implicit NFC or
NFD normalization: canonically equivalent spellings remain distinct until the
language adds an explicit normalization policy. This behavior is regression
tested so compiler hosts cannot change it accidentally.

For compiler compatibility, run `python3 scripts/check-portability.py` to
probe the available `cc`, GCC and Clang frontends and compile the Unicode
implementation and generated tables. On Windows, run the same script from a
developer prompt; it probes MSVC (`cl`) when available. A Clang Windows target
probe is also run when an MSVC-compatible SDK is installed. Pass `--strict` in
CI to make a missing or failing Windows-target probe an error.

This directory is part of the C17 compiler source tree and is covered by
`make -C src verify`.
